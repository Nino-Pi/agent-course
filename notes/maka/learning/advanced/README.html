工程深化课程目录

深度阶段接在 mini-SWE-agent 与 Maka 基础课程之后，围绕输入、状态、动作、继续和评价比较不同设计。14 模块地图可按问题定位推演与参考方案；下列工程路线组织综合设计，产品课按需选读。

第28–47章包括 6 篇工程设计主课、8 篇产品机制详解、3 篇方法深化，以及第35章、第45章的实验与第46章的算法桥接，共 20 章。三篇方法课分别讲隔离后端、代码结构检索、checkpoint 与 replay。Memory/Context 的多实现推导集中在第36章。第60章与第61章负责学后的机制问答与追问解答。

1. 从哪里出发，在哪里收口

第01–10章：最小 Agent 与机制桥接
→ 第11–27章：Maka 核心机制、案例、评价与任务交接
→ 第28–45章：工程设计与代表实现，按机制穿插阅读
→ 第46章：轨迹与学习（算法桥接，选读）
→ 第47章：综合设计与模块衔接
→ 第48–62章：设计问题与完整案例
→ 第63–66章：代表运行支撑与跨场景机制

基础学习从 mini 与 Maka 主线进入。第39章持续工作与协作承接第23章的委派，恢复部分按问题补第18章、第24章和第25章；第40章整项任务评价可从第26章独立进入。

第26章汇总请求循环、输入与事实、未知效果、Memory 写读双链和评价方法。第28章从这些机制出发介绍系统设计；各主题直接呈现状态表、接口与取舍分析。

评价从 第26章 评价最小模型进入：先区分试次、重试、继续、判定与成本，再读 第40章。它与下面的协作主题有独立入口，不要求为了比较两个方案先读完全部调度和 Host 实现。

各主题在同一个修复任务中加入用户并行编辑、长日志、偏好撤回、子任务失败或界面断线，并给出相应的图、接口与处理分支。设计解答按问题对应：架构对应 第48章/第49章；工具对应 第50章/第51章/第52章/第56章；上下文与 Memory 对应 第53章/第54章/第55章；协作与评估对应 第57章/第58章/第59章。

完成对应主题后，可以把同样的问题迁移到个人助理：先读 第31章 跨工具入口的动作授权，再读 第39章 持续委托，接着用第40章通知评价核对分母，最后阅读第47章 七天购买委托的状态推演。这些扩展以 Muse 官方材料引出问题，具体合同和状态演算由课程自拟；完整事实与未证实范围在 Muse 专题。这些教学设计不代表 Muse 的内部实现。

按问题选择代表实现

隔离不可信依赖、跨天恢复、寻找代码和维护偏好需要不同的比较对象。14 模块地图列出各问题的代表实现。

比较时固定同一输入、失败时点和资源范围，说明新机制解决什么问题、增加什么成本。未公开的事务、算法和默认接线保留为未知。

5. 综合设计与条件变化

第47章综合设计将工具、压缩、偏好、协作和恢复接在同一个方案中，直接呈现图、状态表与跨模块失败处理。第26章解释设计依据和评价范围。

第47章的个人助理案例展示从购买委托迁移到报名任务时，状态判断、通知指标和故障处理如何变化。这里给出的是教学推演，不能据此声称运行过 Muse。

第62章提供三组完整设计案例，展示需求变化如何影响接口、状态和恢复方案。图示入口：深度图索引与设计案例图解。

6. 机制解释的层次

各章先解释对象和正常路径，再展示失败分支、实现差异与取舍。产品章中的图说明部件关系，状态表与代码说明每一步如何改变系统。

解释覆盖六个层次：原问题、关键数据结构、状态变化、理论假设、代表实现差异，以及条件改变后的方案选择。问答与案例直接给出推理和参考结果；源码片段说明逻辑，既有运行结果说明相应场景的实际行为。

基础评价之后，算法读者可按需接 第46章 从执行轨迹到学习信号，先核模型实际条件、样本单位与 heldout，再讨论参数学习；开发者无需先读这一支才能完成综合设计。

7. 从机制到完整运行支撑（Agent Harness）

第63章 DeepSeek Harness把配置组合、服务消费和恢复接成一条链；第64章 Pi解释最小核心（Minimal Core）、输入控制与扩展（Extension）的取舍。它们以第14/15/19/23/28/39/44章的相应机制为前置，各章开头给出具体回顾。

通用任务路线先读第65章观察与对象定位（Observation / Grounding），理解旧界面引用为何失效，再读第66章 Muse 个人代理（Personal Agent），把第31/39/40章的授权、持续委托和通知评价连起来。65不依赖63/64的产品细节，66也不要求先读全部代码产品。
