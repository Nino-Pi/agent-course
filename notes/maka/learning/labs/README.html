预写响应与真实模型的区别

第04章、第06章的 DefaultAgent、LocalEnvironment、文件操作和 Shell 执行是真实代码路径。DeterministicToolcallModel 按顺序返回预写响应，不根据 observation 自主诊断。因此这些结果解释的是固定命令序列与记录机制，不能证明真实模型会选择相同动作。

第21章的独立文件部分也是固定输入示例；Maka 部分使用产品实现。第22章分析既有真实模型运行，单次任务结果不代表其他任务的成功率。第35章和第45章的解释以各自已有记录为限，未覆盖的分支仍保留为未知。

第04章、第06章轨迹里的 cost=1.0 是测试模型的合成计数，没有对应 API 账单。成功率、重试和多候选的不同分母见第26章。

案例代码与执行边界

mini-code-lab.py包含三个动作：prepare 复制四文件初始项目并建立本地基线，repair 执行八步脚本，crash 观察被定点终止的子 Agent。初始项目入口列出四份可直接阅读的原始文件。脚本将生成物限定在 .workspace/learning-labs/** 并拒绝覆盖旧结果；这属于脚本的目录检查，LocalEnvironment 仍以宿主用户权限执行 Shell，不会因此获得 OS Sandbox。

结果怎样支持结论

第04章中，失败断言定位秒数余数错误，修复代码解释 % 60 为什么有效，测试结果表明指定用例通过，diff 则排除修改测试来制造通过。不同材料回答不同问题。

第06章中，实际文件证明本地写入是否发生，trajectory 说明 Agent 保存到了哪一步。没有可查询状态的远端副作用不能直接沿用读取本地文件的恢复方式，仍需由效果所在系统确认。
