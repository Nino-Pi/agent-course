第 48 章｜设计问题与参考方案

本章概览

核心问题：一份代码修复 Agent 方案怎样把需求、组件、失败处理和验收条件讲成完整设计？

关键概念：任务合同：成功条件与允许范围；组件职责：谁组装输入、决定或执行；数据流：观察怎样进入下一请求；状态机：工作能否继续或结束；验收：以测试、差异和用户要求检查结果。

关系主线：从固定需求选最小组件，沿一次修复连接输入、动作和观察，再加入失败与并发条件解释取舍；模型的完成声明不能替代实际验收。

1. 问题与已确定的条件

一个 Agent 怎样读取代码、修复问题并验证结果？

采用单用户、本地仓库、一次一个顶层任务的条件。用户允许修改目标函数与 README，要求保留已有改动，不允许修改测试来掩盖错误。成功意味着问题的复现消失、相关测试通过、diff 符合授权范围；模型说“已修复”不是独立完成证据。

这些条件决定最小组件。任务较短时用顺序循环和有界输出；需要跨进程恢复时才增加对应的持久执行合同。多 Agent、向量索引或分布式调度都不是这个起点的必需条件。

2. 完整参考方案

任务入口固定用户目标与授权范围，运行控制器保存工作身份和预算。Context 组装器选择当前规则、任务、已获得的文件与测试结果；模型根据这些输入提出动作。工具执行器校验参数和当前权限，在受控环境中执行，并把结果交回下一次模型输入。

对 125 → 2:25 的错误，循环先读取配置、实现与断言，确定测试入口；执行测试获得实际差异，再根据一般的分钟/余秒契约修改。编辑成功之后仍需复测并检查 diff。模型负责解释结果，程序负责执行、记录和停止条件。

若任务变长，Context 压缩改变后续输入表示，原始事实继续保留。若要未来沿用语言偏好，则需要独立 Memory 写入、读取和注入。若要求崩溃恢复，可能产生效果的操作在执行前后保存身份与结果；结果未知时先向资源 owner 核对，不能直接重做。

4. 一份已填写的设计记录

以下是教学方案的配置记录，用来说明字段各自约束什么；不是 Agent SDK 或可直接启动的配置。

design = {
    "scope": {"user_count": 1, "workspace": "local", "top_level_tasks": 1},
    "allowed_writes": ["README.md", "src/duration.js"],
    "acceptance": ["一般分钟/余秒契约成立", "相关测试通过", "保留用户改动"],
    "owners": {
        "task_and_budget": "run_controller",
        "file_commit": "workspace_executor",
        "accepted_results": "result_store"
    },
    "normal_path": ["读取", "复现", "诊断", "条件编辑", "复测", "检查差异"],
    "failure_policy": {
        "stale_file": "重新读取，保留并发修改，再决定补丁",
        "effect_unknown": "查询或对账，不直接重做",
        "budget_exhausted": "停止新调用，结算已开始操作并报告未完成范围"
    }
}

allowed_writes 表达政策，真实执行器仍需落实路径和资源边界。file_commit 的条件提交要由资源 owner 实现，不能只靠配置字段获得。accepted_results 保存运行程序接纳的结果；它不能替代外部文件或服务的状态。

例如文件已经变成期望内容而操作回执丢失，只能确认“当前内容符合目标”；没有可靠回执时不能断言一定由原调用完成。这不妨碍继续有权限的验证，但阻止无依据的重复写入。

6. 常见设计问题与完整回答

为什么不直接用多 Agent？ 两个短文件的读取可以通过并行工具完成。子 Agent 适合独立多步探索或需要隔离的大量上下文；新增身份、输入、等待和交付都有成本。只有可独立验收的子任务，才提供有意义的委派边界。

必须用事件溯源吗？ 不必。恢复、审计与 UI 重建各需要某些事实，可以由状态表、追加记录或组合满足。选择依据是哪些状态要原子更新、哪些过程要重放、哪些记录要跨重启保留，而不是先选择架构名称。

类型定义了 safe=true 就安全了吗？ 类型约束数据形状，真实效果还要经过可信授权与执行限制。版本条件必须在提交时成立；取消也必须由执行入口处理。字段存在不证明这些行为已接线。

方案和运行结果是什么关系？ 本章给出可实现的责任与合同，尚未报告运行结果。实际测试只能支持所覆盖的输入、环境和故障窗口；一次正常修复不能证明所有工具都能安全恢复。产品比较也分别保留源码事实、公开设计与自拟方案的边界。
