第 46 章｜执行轨迹与学习信号

本章概览

核心问题：怎样从执行轨迹构造学习信号，并检验改参数、存经验或改程序是否改善任务表现？

关键概念：Rollout（任务尝试）：一次可含多次调用的完整尝试；状态与观察：现实情况和模型所得信息；Mask（位置掩码）：指定参与损失的生成位置；Reward／Credit（奖励／归因）：评价结果并分配学习信号；Surrogate（代理目标）：局部优化式；Heldout（保留评估集）：未参与方案选择的任务。

关系主线：保留真实输入和尝试分组，再定义局部训练目标；用配对任务检查经验收益，章末选读区分任务程序与改进程序。切片、存储和程序修改本身都不等于能力提升。

第26章区分了一次任务、计划试次与有效评分；第40章又用同一张表说明，未知不能补成失败，切换分母也会切换所回答的问题。现在要把这些执行记录用于改进Agent：先回答每个决策当时看见什么，再决定哪些位置得到什么学习权重，最后用新任务检查效果。得到一份可训练的材料，与已经学得更好，是这条链上的不同结果。

1. 一次 rollout，不一定是一条不断变长的文本

rollout 在本例指一次从规定初态开始，到终止并记录状态的完整任务尝试。任务分数可能因验收程序无法运行或未返回结果而缺失；这与验收正常完成后判为失败不同。“尝试结束”不保证“得到了有效分数”。它可以有多次模型调用、工具执行和等待。工具调用次数、模型调用次数和 rollout 数是三种统计单位，不能相互替代。

沿用课程中的 formatDuration 修复情境：函数把非负安全整数秒写成“分钟:两位余秒”，例如125秒应为2:05；任务需要修正余秒计算，并让README指向实际测试入口。下面是独立教学轨迹，不是第04章的原始运行或真实 token 记录。每行的动作可能需要多段输出；本题只保留理解学习材料所需的关系。

文件内容、未完成进程、权限和工具状态属于执行环境。模型只能基于本次输入选择下一步；即使环境里已经出现新文件，没有被读入本次输入也不等于模型知道它。学习时因此要问“当时实际提供了什么”，不能事后把完整正确答案补进旧输入。

在 Maka，下一次模型输入还可能由 durable 事件的有效投影、摘要或工具结果引用重建。跨一次 compaction 后，C3 的 prompt 未必是 C2 输入加输出的严格延长；子任务的输入也可能重新构造。真实链见 第15章 模型输入与流和 第19章 checkpoint 消费。缓存、压缩、检索分别改变复用、表示与选源，不决定训练 reward。

Markov 条件要求所选状态已包含预测下一转移与反馈所需的信息，再补更早历史不改变这种条件分布；给 transcript 起名 state 并不能满足它。MDP 的完全观察设定让决策者看到这种状态；POMDP 仍以底层 Markov 状态转移，但决策者只得到观察。保留历史有助于消除歧义，压缩后的 hth_tht​ 却不保证仍是充分统计量——也就是“不损失预测/决策所需历史信息”的表示。

这些条件不能反向滥用：两个状态不同，并不意味着每个动作的后继分布都必须不同；只有最近六条文字，也不足以证明它在每个任务中一定不充分。应找出具体被遗漏、且会改变预测或决策的信息。受控读回能否区分两种世界，还取决于读到了什么；重复读取同一不相关页面仍不能提供所需证据。

例如 Edit 已把文件写好，回执却丢失：真实 st+1s_{t+1}st+1​ 已改变，下一输入 ht+1h_{t+1}ht+1​ 只有超时或未结算信息。另一种世界是 Edit 根本没有写入，两者此刻可产生相同观察。策略不能仅凭超时断定应该重写；应按授权与恢复合同重新读取或查询效果。这个例子说明为什么状态、观察和保存不能合并，它比较的是两种可能的执行状态。完整效果问题回到 第18章，有限观察的现有讨论见评估专题。这种表示不证明 Agent 已拥有正确的环境模型或 POMDP 求解器。

token 是 tokenizer 处理后的序列单位，不必等于一个汉字或英文词。mask 是每个位置是否参加这项损失计算的指示。本题输入和工具返回位置为 0，模型生成位置为 1；其他训练目标可能另有规则。mask 只决定哪些位置直接贡献训练项，不负责核实条件文字是否真实。

例如 C2 的输入有“Read 返回：第 8 行使用旧算法”，输出是一个 Edit 调用。该 Read 文本属于输入，不能当作模型生成的正确答案一起奖励；否则模型可能被训练去生成环境本应提供的观察。若 Read 实际失败，把它事后改成成功内容，即便对应 mask 为 0，Edit 的条件也已经被伪造。

已有 RuntimeEvent 账本、摘要指纹或可回放消息可以帮助查来源，但不能单独证明真实 token、采样分布与 log probability 已完整保存。还需按训练算法的数据合同检查，才能决定是否可用。

切成几段，为什么会改变统计权重

以下按 Agent Lightning v1.0 图 4 转写教学演算：两次 rollout 的 reward 为 1、0；成功尝试切成三个样本，失败尝试只有一个。按 rollout 平均是 (1+0)/2=0.5，摊平后按样本平均却变成 (1+1+1+0)/4=0.75。样本变多没有增加任务尝试，分组身份不能丢。

差别来自权重：原来两次尝试各占一半，摊平后成功尝试的三个片段合计占四分之三。若仍想按尝试等权，并选择在每次尝试内部按片段等权，那么成功尝试的每片应占 12×13=16\frac12\times\frac13=\frac1621​×31​=61​，失败尝试的一片占 12\frac1221​；加权reward又回到0.5。这里先用片段说明分组为何重要；下节另选按生成token平均，不能把两种单位混称为同一归一化。

重序列化可能破坏真实 token 前缀，合并与 loss 归一化需要显式处理。

对我们的修复，可先保存 C1…C4 的独立条件样本，再明确是否满足合并条件。仅因它们属于同一任务，不能把被压缩的旧全文重新拼进 C3；这样得到的是另一条模型从未看到过的轨迹。

2. reward 给结果，credit 给决策分配学习信号

reward 是明确规则给出的标量反馈。本题为了演算，令有效任务成功得 1、有效失败得 0；这不是规定所有 benchmark 都只能用二值评分。credit assignment 问的是：多个决策共同产生结果，应该怎样给它们分配学习信号。

若 C1 在必要源码之外又读了三个无关文件，C2 的一次 Edit 修好了核心错误，整次 rollout 可以成功；把终局 reward 放到所有调用上，会同时鼓励必要动作和多余动作。这是一个可采用的分配规则，不能据此证明每一步都促成成功。反过来，最后测试因基础设施不可用而没有结果，也不能立即把此前每个决策判为能力失败。

这里还要分开三种常见反馈：Maka Goal 的 met 用来决定是否继续；任务 grader 的 score 用来评价产物；训练 reward 则是算法明确选定、附带缺失处理政策的学习信号。字段之间可以有经过设计的映射，不能只因为都是“评估结果”就自动互换。继续阅读 第40章 的结果消费与评价。

固定批次上的局部训练目标

先只看一个生成位置。策略 πθ\pi_\thetaπθ​ 表示参数为 θ\thetaθ 的模型给定当前输入时，产生各候选输出的概率。把已经生成的token记为 xxx，它的实际条件前缀记为 ppp；q=πθ(x∣p)q=\pi_\theta(x\mid p)q=πθ​(x∣p) 是模型赋予这个输出的概率。小写 ppp 在这里表示前缀，不表示概率数值。

第一步：从概率走到log概率。 本节的 log⁡\loglog 指自然对数，并取 0<q≤10<q\leq10<q≤1；概率为0时不能直接代入有限的log值。此范围内的对数不大于0，概率越大，对数也越大。例如教学假设 qqq 从0.2升到0.4，log⁡q\log qlogq 从约−1.6094升到−0.9163。对同一次调用生成的一串token，条件概率按生成顺序相乘，取对数后转成逐位置相加。因此，可以为每个生成位置建立训练项，再汇总；跨调用仍须使用各自的真实输入，不能借求和把旧全文补回。

第二步：用有符号权重指定局部方向。 设这个位置分到固定权重 AAA，定义：

ℓ(q;A)=−Alog⁡q,dℓdq=−Aq(q>0).\ell(q;A)=-A\log q,\qquad \frac{\mathrm d\ell}{\mathrm dq}=-\frac{A}{q}\quad(q>0).ℓ(q;A)=−Alogq,dqdℓ​=−qA​(q>0).

导数描述 qqq 稍微变化时损失怎样变化。当 A=+0.5A=+0.5A=+0.5，上述概率增加会使损失从约0.8047降到0.4581；当 A=−0.5A=-0.5A=−0.5，损失则从约−0.8047升到−0.4581。于是，减小这项损失分别偏向提高正权重输出的概率、降低负权重输出的概率。局部损失可以为负，它的零点不表示任务刚好合格；这里也还没有执行模型更新。

把两个平均因子与reward权重相乘，成功token的log概率系数为 −12×16×12=−124-\frac12\times\frac16\times\frac12=-\frac1{24}−21​×61​×21​=−241​，失败token的系数为 −12×12×(−12)=+18-\frac12\times\frac12\times(-\frac12)=+\frac18−21​×21​×(−21​)=+81​。成功项希望提高其输出概率，失败项希望降低其输出概率；共享模型参数仍可能牵动其他输出，不能由一个系数保证所有token概率都独立朝该方向变化。

成功尝试的六项系数合计为−1/4，失败尝试的两项合计为+1/4，反映两次尝试等权、信号方向相反。这是系数的合计，不是损失数值，因为各位置log概率还会不同。只要参与token总数和实际条件不变，将成功的6个token分成三个样本不会改变这些系数；实现若在切片后重新给每片一整份rollout权重，就破坏了这项设计。

这是固定批次、固定权重的局部 surrogate（代理目标）。归一化按 rollout token 均值是显式设计选择；它不是完整的近端策略优化（PPO）或组相对策略优化（GRPO），不声称无偏估计原始未归一化回报目标。旧策略数据校正、重要性比率、衡量分布差异的 KL 约束、裁剪或价值估计训练，都属于此处尚未展开的完整算法问题，不能由这一条 loss 式补出对应保证。

基础依据是策略梯度：策略采样整条轨迹，目标是其预期回报；轨迹 log probability 的可优化部分来自模型动作。baseline 可减少估计噪声，但需要满足所用推导的条件。对于上述有限批次，loss 下降本身并不保证未来回报提高，不能把同一批样本一直优化到最小后便宣称能力改善。

数据实现需要交代实际输入、mask、rollout 分组和 outcome 的来源。算法设计还要检验权重估计、采样策略、长短轨迹的相对权重、方差与偏差，以及何种 heldout 结果会推翻设计。

3. 用新任务检查，而不是把训练信号当交付证明

需要三种不同用途的数据。training 产生更新模型参数的信号；validation 用来选 checkpoint、prompt 或超参数；heldout 是保留到评估阶段、没有被这些选择反复使用的任务。名称不决定身份，实际用途才决定。

例如团队用一批时间格式化缺陷训练，再用另一批问题选择 reward 与训练轮数，最后在未用于这些选择的缺陷和项目上评价。如果最后一批每次失败都被拿来改 prompt、加规则，再重报最好成绩，它已经参与开发选择，不能继续当作未触碰的最终检验。把同一题换几个变量名，也不自动获得独立任务分布。

grader 的参考答案与测试还要有明确边界：用于产生训练 reward 的规则可以是训练环境的一部分，但若 Agent 直接读到参考修复并照抄，得分衡量的对象已经改变。最终 heldout 的题目、答案和调参反馈更不能通过输入、目录、历史或检索意外进入训练/选择过程。是否泄漏要沿实际数据流检查，不能靠把目录命名为 heldout 来保证。

第40章 表中的 I/M仍是训练入口的检查点。没有任务分数时，默认填 reward=0 会把基础设施可用性混入能力训练；删除它们又可能留下一个偏向容易运行任务的数据集。若目标确实是按时交付，可以单独定义“截止前确认成功”的反馈，但要声明这一目标、缺失政策和费用，并继续保留原状态供分析。

以下四题、回答和费用均是完整给定的教学轨迹，没有运行模型。两边按 X1→X2→X3→X4 的相同次序，各题各有一个计划试次；每题最多3次模型调用、2次工具调用、60秒和8个费用点。费用点是便于比较的虚构账本单位，不是实际价格。读写笔记也占各题同一份预算，不给 K 额外的调用额度。

4. 切片、输入与评价变化后的参考结论

题 1。 一个成功 rollout 因摘要和子调用切成十个样本，一个失败 rollout 只有一个。团队写“训练集中 10/11 的任务成功”，并直接按样本求 reward 均值。哪里改变了研究对象？

答案。 实际仍是两个任务尝试，成功比例为 1/2；10/11 是切片加权后的比例。直接按样本平均会让易被切分的 rollout 获得更多权重。应保留分组，明确按 token、sample 还是 rollout 归一化，再按目标评价这种权重；不能把 token/mask 正确当作分组权重也必然正确。

题 2。 C2 后做了摘要，C3 只见到摘要与当前约束。为减少训练样本数，导出器把 C1/C2 的全部旧文本拼回 C3，再计算 C3 输出的 log probability。只要内容事实没错，就等价吗？

答案。 不等价。训练条件已经不是实际采样条件；旧全文与摘要可能表达不同细节，也有不同 token 前缀。先保留真实调用输入，只有满足所用算法要求的精确前缀与 mask 条件才合并。若要用重构条件训练，应明确它是另外一种数据与目标设计，不能标成原轨迹保真导出。

题 3。 本章局部 loss 连续下降，最终 heldout 的确认交付率却下降。团队能否用“已经奖励了成功动作”宣布学习有效？若 heldout 失败来自 verifier 宕机，又该怎样处理？

答案。 不能。局部 loss 只是当前样本与目标下的优化信号，任务效果要按事先固定的 heldout 口径评价。先区分有评分的任务失败与 I/M；分别报告条件质量、确认交付、费用和未知，再查数据条件、权重、策略漂移与选择偏差。verifier 宕机不能无说明地当模型能力 reward=0，也不能删掉后仍宣称整体交付无退化。

从调用到训练假设的完整参考例子。 一个成功尝试 R1 包含 C1–C4 四次调用，导出为四个保留真实输入的样本；一个失败尝试 R2 在两次调用后结束，导出两个样本。数据关系为 R1 → {C1,C2,C3,C4}、R2 → {C1,C2}，统计仍是两次 rollout。若把 reward 原样复制后按样本平均，得到 4/6=2/3；按 rollout 平均则是 1/2。这两个数描述同一批数据的不同权重，没有产生四次新的成功尝试。

参考训练假设是：固定训练轨迹、初始模型、优化步数、工具权限及总训练预算，只把切片等权改为每个 rollout 内生成 token 平均、再对 rollout 等权，期望减少长成功轨迹因切片获得的额外权重，并在预先固定的 heldout 任务与预算下，使截止确认交付率提高至少 5 个百分点。这里的 5 是待检验的设计阈值，不是已取得的提升；归一化改变权重是确定的，未来质量改善仍需独立评价。

不确定性的参考判定也可以提前写清。假设采用事先固定、考虑 task 聚类的方法得到提升区间 [+1,+8] 个百分点，它仍包含低于 5 的值，不能确认“至少提升 5”；若区间为 [-4,+2]，则在该方法与置信水平下排除了所声称的 5 点提升，却没有证明任何微小收益都不存在。这两组区间仅演示判定规则，不是实验结果。没有足够证据确认提升，与证据排除了指定提升，是不同结论；缺失评分和费用仍按第40章的固定口径保留。

5. 选读：任务程序与改进程序怎样分别变化

存下一条经验、修改模型参数、改写执行程序，是不同的更新对象。再往前一步，还可以修改“产生改进方案的方法”。本节用一个有限案例把它们分开；所有程序、结果和预算都是教学设定，既不是已经发生的自主实验，也不是 Hyperagents 论文的复现。

先给两个可编辑对象命名：task 程序 A 接收一个代码维护任务，决定怎样修改、验证和报告；meta 程序 M 读取开发轨迹，生成 A 或 M 自身的新版本。它们处在同一个允许编辑的教学程序包中，但题目、独立判定器、预算和采纳规则由外层执行器持有，A/M 都不能改写。

本题的完整交付要求是“修改符合范围、指定行为正确、报告附有本次有效验证依据”。因此“有验证记录”只是一个检查项。外层判定器即使看见一份记录，也还要检查实际命令、产物和覆盖范围；没有记录但提交了产物时，它也可以正常给出有效失败 F。它与判定环境根本无法给分的 I/M 不同。

这里都是有效评分，A0 为3/5，A3为4/5，配对平均差 1/5=0.2，即20个百分点。H4 仍失败，不能用“采纳合同通过”宣称交付所有任务，也不能因为 D/V/H 的比例不同就只挑最高的6/6报告。五例不足以证明推广显著性。

这一轮给出了可变对象、提案、拒绝理由、冻结与最终对照，说明“改进程序也能被修改”究竟多了什么。但只看 M1 产生过一个好候选，还不能证明它普遍更善于产生改进；要评价 meta 本身，应从相同起点、相同候选生成预算比较 M0/M1 所产生并被实际选择的后继，而不是只比较两个 task 的分数。

Hyperagents 提供了把 task 与 meta 放进同一可编辑程序的研究方向。其主实验仍有外层选择与评价机制，并维护候选 archive；本题只采用有限的候选流程帮助理解，不把它冒充论文完整搜索算法，也不从自修改能力推出无限进步、开放领域安全或持续学习已经实现。读到这里即可把三件事分清：保存经验改变下一次可见信息，改 task 改变解题方式，改 meta 改变提出后续改进的方式。
