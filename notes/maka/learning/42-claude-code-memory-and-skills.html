第 42 章｜Claude Code：自动记忆（Auto Memory）、规则（Rule）与技能说明包（Skill）

本章概览

核心问题：持续默认、本次例外与复用方法，怎样到达恰当任务并影响行为？

关键概念：项目指令（Project Instructions）提供持续指导；自动记忆（Auto Memory）保存未来可能需要的背景；索引（Index）帮助发现条目；作用域（Scope）限制适用对象；技能说明包（Skill）组织按需方法。

关系主线：保存和读入分别建立材料与线索，当前要求决定本次选择；方法正文、子代理（Subagent）输入与工具预批准（Tool Pre-approval）各有独立的消费者（Consumer）和寿命。

前情回顾：长期背景、当前进度与权限（Permission）分开

第20章与第36章说明，长期记忆（Long-Term Memory）的价值取决于未来是否取回和正确使用；第23章说明，技能说明包（Skill）是可复用方法，子代理（Subagent）则需要实际收到目标、背景和限制。本章把这些概念放进 Claude Code 的文件读取与方法装载合同，先追踪材料，再判断行为。

第33章还区分权限（Permission）与自然语言指导：正文“只读”影响模型（Model）的选择，实际工具（Tool）和执行环境（Environment）决定能否写入。本章会用 allowed-tools 说明，方法仍在模型输入（Model Input）里，不代表先前许可仍有效。

沿用 Python 文档扫描器：scan.py 读取指定目录的 Markdown 文件并检查链接，含空格路径曾引出参数边界问题；项目说明和测试配置给出检查入口。本章新关注检查报告的语言与调查方法，不假定前章未完成的修复已经通过，也不扩大文件写入范围。

用户先说“这个仓库的报告用中文”，后来要求“这次给外部协作者的报告用英文，代码注释规则不变”。下面给出三次会话（Session）的完整参考过程，以及一份只读调查技能说明包（Skill）的完整定义。它们是教学情境，未在 Claude Code 中创建自动记忆（Auto Memory）、安装方法或实际执行。

1. 从“记住了”拆出保存、发现、读取和应用

同一次会话（Session）里，两条语言要求都在，模型（Model）仍可能套错；换到下一次会话（Session），还多了是否保存、是否读入的问题。文件存在，只证明存储载体存在，不证明当前模型输入（Model Input）已经包含它。

Claude Code 区分人工维护的项目指令（Project Instructions）与自动记忆（Auto Memory）。前者以 CLAUDE.md 等持续指导表达约定，后者保存可能帮助后续任务（Task）的背景。两者参与模型输入（Model Input），都不是硬权限（Permission）控制。这里与第33章的边界一致：想让某条要求成为执行限制，需要对应的工具（Tool）或权限规则（Permission Rule）。

自动记忆（Auto Memory）用自己的 MEMORY.md 索引（Index）与主题文件组织材料；与 Maka 的文件同名，不表示同一文件、同一负责者（Owner）或相同读取规则。默认存储按仓库归组，同一仓库的工作树（Worktree）共享；机器与云环境之间不自动共享。显式存储配置可以改变位置，所以“每个工作目录必有完全独立自动记忆（Auto Memory）”也不成立。

启动时读入 MEMORY.md 的前 200 行或 25KB，以先到者为限，主题文件按需读取。索引（Index）让模型（Model）发现“报告语言”条目，详细内容再解释默认和例外；这两步不能用一条“保存后自动用到”箭头代替。官方记忆合同规定了这些可见读取行为，没有由此公开完整的向量检索（Vector Retrieval）、语义去重（Semantic Deduplication）或原子写入（Atomic Write）协议。

2. 四类材料分别由谁消费

同一句“保存一下”，可能指未来偏好、当前任务（Task）进度，也可能指恢复文件。先辨认保存对象，才能找到负责者（Owner）和消费者（Consumer）。

对扫描器，各种材料的去向也可以具体判断：

  • “遵循项目文档规定的测试入口”可作为简短项目指令（Project Instructions），但命令是否仍有效要查当前项目。
  • “本仓库报告默认中文”是带作用域（Scope）的偏好；本次英文要求是当前例外，不能悄悄升级为永久默认。
  • “链接检查报告的固定步骤”适合按需装载的技能说明包（Skill）。
  • “已修实现，空格路径用例尚未复测”属于当前任务连续性（Task Continuity）。
  • “编辑前的 scan.py 内容”属于文件恢复资料，交给检查点（Checkpoint）一类机制处理。

分配材料不只是节省词元（Token）。它让修改对象明确：更新默认规则、纠正自动记忆（Auto Memory）条目、替换调查方法、恢复一段代码，分别需要不同操作，不能因为都用文件存储就混在一起。

3. 自动记忆（Auto Memory）的写入与使用怎样闭合

先看语言偏好怎样穿过系统。用户当前要求可以直接进入本次判断，不必先持久化（Persistence）；只有被认为对未来有用的材料，才需要进入自动记忆（Auto Memory）的写入与后续读侧。

图中“判断作用域（Scope）与未来用途”“结合当前要求和相关自动记忆（Auto Memory）”是课程概括的职责，不表示宿主（Host）对所有语义冲突都具有确定性求解器。可读文件使记录可检查，选择是否正确仍要看材料和实际行为。

每一行都可能独立失败。保存成功不证明入口可见，索引（Index）可见不证明详细文件已读，读过也不证明推理时选择正确。发现行为错误时，沿这些状态定位缺口，比重复写同一条自动记忆（Auto Memory）更有用。

4. 三次会话（Session）：默认和例外怎样相处

会话（Session）A：建立默认。 用户说本仓库报告使用中文。本例先把对象限定为“报告”，把作用域（Scope）限定为“当前仓库”，把有效方式限定为“持续默认”。它不涉及测试数据和代码注释，也不自动适用于所有仓库。

会话（Session）B：出现局部例外。 用户要向外部协作者交付本次英文报告。模型（Model）按当前请求输出英文；后续整理时，不能把这次例外写成全局偏好。若确有未来用途，可以记录本次交付对象与语言的有限事实，并明确后续需要重新确认。

会话（Session）C：没有重述语言。 用户只说“生成最新检查报告”。如果相关索引（Index）与条目被取回，并且没有新的相反要求，中文默认才适用于本题。此时需要观察保存、读取与采纳的完整过程，不能只检查最终语言。

可以用一个局部判定式解释这条默认的适用条件（Applicability）。令 RRR 表示当前仍在约定仓库，DDD 表示正在写检查报告，EEE 表示当前用户明确指定其他语言；那么本题中应用中文默认的条件为：

A=R∧D∧¬EA = R \land D \land \neg EA=R∧D∧¬E

这里 AAA 只表示本例默认是否适用，不是 Claude Code 的内置规则计算器，也不判断条目是否已保存或已读取。会话（Session）B 中 EEE 为真，所以不能套默认；会话（Session）C 中若 RRR、DDD 为真且 EEE 为假，默认适用。若当前处理代码注释，则 DDD 为假，这条报告偏好不应改变注释。

“输出中文”仍不能单独证明自动记忆（Auto Memory）产生了作用：系统指令、界面语言或用户本次中文输入都可能解释结果。归因需要控制其他来源、检查实际读入材料，并用移除相关条目的对照比较。这是评价设计，本章没有把它写成已执行实验。

5. 容量（Capacity）与冲突（Conflict）：文件存在仍可能用错

索引（Index）过长与条目互斥是两种故障

第一种失误是把索引（Index）写成手册，前面全是详细步骤，关键例外放在后面。即使完整文件保存成功，启动读取上限仍可能挡住后半部分。按当前公开合同，超限写入本身可以成功，同时返回要求重写索引（Index）的错误；这不是“错误就证明文件没有变化”。参考处理是让每条入口只表达主题、适用条件和条目位置，长过程转入技能说明包（Skill）或详细文件。

第二种失误是两个条目同时自称默认：旧条目写报告中文，新条目写报告英文，却都没有作用域（Scope）和例外。即使全读进来，模型（Model）仍缺少选择依据。应纠正对象和条件、移除已失效内容，而不是继续追加“务必记住”一类形容词。

完整记忆内容（Memory Content）：把适用与失效条件写出来

下面是课程自拟的 YAML 内容，不是 Claude Code 强制要求的结构（Schema）。subject 与 scope 定位对象，default 和 exception 区分默认与本次覆盖，最后两项限制误用与指出何时复核。先理解这六项职责，再读完整示例：

subject: 扫描器报告的语言
scope: 当前仓库的日常检查报告
default: 中文
exception: 当前用户明确指定其他语言时按本次要求
does_not_apply_to:
  - 代码注释
  - 测试 fixture 中的原始字符串
review_when: 团队报告规范发生变化

does_not_apply_to 用明确反例防止过度泛化，review_when 给出失效条件（Invalidation Condition）。简单偏好可以用更少字段，只要仍能分清适用范围；这些字段没有让模型（Model）自动获得事务性冲突处理，也不是一份实际运行输出。

6. 技能说明包（Skill）：从发现线索到可执行方法

项目指令（Project Instructions）“提交前运行检查”还没有说明怎样检查链接、理解失败和组织报告。技能说明包（Skill）可以提供按需方法；官方功能分工把持续指导、按需知识和独立工作分开，本题也应按实际消费者（Consumer）组合它们。

对于扫描器，完整方法可以是确定输入目录、找到验证入口、执行相关检查、区分无效链接与不可访问对象、给出带验证范围的报告。用户若只问一个函数含义，整套流程可能不需要装载。方法有步骤，也要有停止条件（Stop Condition）：入口不存在、信息不足或实际能力不允许时，应返回具体缺口，而不是凭名称猜一次成功。

可见的名称与描述承担发现（Discovery），正文承担方法装载（Loading）。描述太泛可能误触发，遗漏常用说法又可能漏触发；“修复坏链接”应命中，“解释 Python 列表”不应命中，是本题两条可比较的正反例。用户明确调用时，还需提供具体调查对象。文件中有一套正确方法，不证明选中了它，也不证明其中检查已经执行。

7. 执行上下文（Execution Context）与预批准（Pre-approval）分别选择

装载方法之后，还要决定由当前会话（Session）执行，还是由子代理（Subagent）接收自足的子任务（Subtask）。下图表达这两种消费位置；实际调度和后台顺序由对应执行路径决定。

技能说明包（Skill）的 context: fork 会新建所选类型的子代理（Subagent），把正文作为任务（Task）输入。它不复制父对话历史（Parent Conversation History）；不能按对话分叉（Conversation Fork）理解。父任务（Parent Task）中已经说明的仓库、报告要求和限制，若是子任务（Subtask）必需信息，就要进入它实际收到的正文或参数。

工具预批准（Tool Pre-approval）另有寿命：allowed-tools 让列出的工具（Tool）在调用该技能说明包（Skill）的工作轮次（Turn）免于逐次询问，下一条用户消息（User Message）到达后清除。未列出的工具（Tool）仍受其正常权限规则（Permission Rule）控制，这不是仅准调用所列工具的白名单。

方法正文则作为消息（Message）进入对话，可在后续工作轮次（Turn）继续存在；内容仍在，不代表预批准（Pre-approval）仍在。反过来，配置广泛预批准（Pre-approval）也不把正文“只读审查”变成硬限制。方法内容、可调用工具集合与权限（Permission）要分别判断。官方技能说明包合同明确了这项区别。

8. 只读调查技能说明包（Skill）的完整参考定义

下面沿用公开字段构造完整教学示例，未创建真实技能说明包（Skill）或执行调查。先读配置与正文的分工：名称和描述解释方法用途，disable-model-invocation 控制调用入口，context 与 agent 选择子代理（Subagent），正文给出对象、限制、处理步骤、交付与缺失出口。

---
name: inspect-link-checker
description: 调查指定目录的 Markdown 链接检查流程，返回检查入口和潜在失败原因
disable-model-invocation: true
context: fork
agent: Explore
---

调查 $ARGUMENTS。

任务限制：只读取文件，不修改，不上传项目内容。
1. 找到扫描器入口和测试配置。
2. 确认含空格目录如何穿过参数边界。
3. 区分已读代码事实与需要实际运行才能确认的假设。
4. 返回：入口、参数流、可疑位置、建议检查、未完成项。
若找不到目标目录，明确返回缺失信息。

$ARGUMENTS 提供调查对象，不能只写“前面那个目录”。正文让子代理（Subagent）知道需要沿入口、参数流和可疑位置调查，同时区分已读源码与待验证假设。若目标目录不存在，完整参考结果应明确“未找到目录，入口、参数流与故障判断尚未确认”；不能把没有材料等同于没有问题。

agent: Explore 的工具（Tool）能力由产品定义。当前官方合同中，这种类型还会省略 CLAUDE.md 与 Git 状态背景，所以示例把必要限制直接放入正文；不能期待它从主会话（Session）自动继承。正文“只读、不上传”表达本题要求，仍不能替代实际工具（Tool）与权限（Permission）的控制。

disable-model-invocation: true 阻止模型（Model）自动装载该技能说明包（Skill），供用户明确调用；默认发现线索也不进入模型输入（Model Input）。它不是仅仅“偏向手动”。若改成可自动发现的方法，就需要足以区分相邻任务（Task）的描述，并评价误触发。是否后台执行、怎样等候和接收完成，放到第43章继续解释。

9. 三个反例：信息与文件没有统一的隔离边界

反例一：压缩（Compaction）后记得偏好，却忘了测试失败。 两者不矛盾。长期背景与当前任务（Task）摘要是不同链；能读到中文偏好，不证明失败位置、已改文件与未复测状态保留完整。应重新读取关键错误，不能以正确语言风格掩盖功能状态未知。

反例二：父任务（Parent Task）装载了技能说明包（Skill），子任务（Subtask）却不知道规则。 独立执行的初始化不等于主任务（Task）当前输入。必须看子代理（Subagent）接收的是任务说明（Brief）、对话分叉（Conversation Fork），还是方法正文驱动的上下文（Context），再补足必要材料。已装载过不代表所有后代都继承。

反例三：两个工作树（Worktree）同时修改同一自动记忆（Auto Memory）主题。 代码工作副本（Working Copy）隔离，不保证长期背景也隔离；同仓库默认共享自动记忆（Auto Memory）目录。公开文件接口（Interface）没有给出完整并发冲突协议。一个教学方案是让同主题由单一写入负责者（Owner）提交，把旧版本作为更新前提；冲突时保留双方意图并重新判断作用域（Scope）。这是额外设计，不是工作树（Worktree）自动提供的记忆事务。

把失败条件与参考结果一一对应，可以检验解释是否完整：

索引与详细记忆（Index / Memory）少量入口暴露线索，内容可检查发现或读取可能失败能否找到正确默认和例外？
技能说明包装载（Skill Loading）方法可复用，可独立维护发现与触发需要评价是否定义了任务（Task）、产物和停止条件（Stop Condition）？
技能说明包独立上下文（Skill Context）调查过程不占满主任务（Task）输入父背景可能缺失，结果要整合能否提供自足任务说明（Brief）？

拆文件也要看消费者（Consumer）。若长手册被拆成多个文件，却仍由 CLAUDE.md 在启动时全部导入，总输入成本不会仅因文件数变多而降低。真正按需读取要让入口足够清楚，并确认需要时能取到详细内容。

Maka 与 Claude Code 都在常驻成本和按需漏读之间取舍，但同用 Markdown 不表示作用域（Scope）、读取顺序或权限（Permission）语义相同。

11. 常见场景与完整参考结论

题一：项目指令（Project Instructions）、自动记忆（Auto Memory）、压缩（Compaction）与检查点（Checkpoint）分别回答什么？

参考答案：CLAUDE.md 等项目指令（Project Instructions）提供持续指导，自动记忆（Auto Memory）提供后续可能使用的背景，压缩（Compaction）组织当前长任务（Task）的输入，检查点（Checkpoint）追踪特定文件恢复状态。对象与消费者（Consumer）不同，不能用一条“保存”箭头互相替代。

题二：索引（Index）写入成功，为什么新会话（Session）仍没用到条目？

参考答案：检查入口是否在启动读取范围、描述是否相关、详细条目是否实际读取、当前要求是否覆盖默认，以及最终是否正确应用。超限写入仍可能发生，不能看到错误就认定文件没改；也不要尚未定位缺口就反复保存同一条内容。

题三：把手册拆成多个被 CLAUDE.md 导入的文件，能省上下文（Context）吗？

参考答案：若仍在启动时展开全部内容，拆分主要改善维护。要减少常驻成本，需要按任务（Task）或路径装载，并确认所需资料可被找到。磁盘文件数不能代表模型输入（Model Input）大小。

题四：技能说明包（Skill）的 allowed-tools 为什么不是安全白名单？

参考答案：它提供调用工作轮次（Turn）的临时预批准（Pre-approval），下一条用户消息（User Message）会清除；未列出的工具（Tool）仍按正常权限规则（Permission Rule）判断。方法正文持续存在也不会延长这份许可，需要硬限制时仍应使用实际能力与权限（Permission）机制。

题五：独立技能说明包（Skill）只写“按前文分析”会怎样？

参考答案：context: fork 不提供父对话历史（Parent Conversation History），子代理（Subagent）可能只收到含糊任务。应提供明确对象、必要背景、限制、交付和缺失出口；确实依赖历史（History）时，要评估真正的对话分叉（Conversation Fork）等初始化方式。

题六：用户把报告默认从中文改为英文，怎样区别于本次例外？

参考答案：这次措辞明确改变默认，应定位旧作用域（Scope），更新或撤销旧条目，避免两个默认并存。后续新会话（Session）未重述语言时，参考输入应包含英文默认，参考输出为英文报告；只有实际读取与输出记录能证明这条链发生过。已有历史报告无需无关改写。
