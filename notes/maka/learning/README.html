课程学习路线

课程按 01–62 连续编号，所有编号正文位于同一目录。按文件名排序即可依次阅读，每章末尾也有上一章、下一章链接。课程以代码修复任务为主线，每章直接呈现概念、代码、案例过程与参考结果。没有 Agent 经验可以从第01章开始；完全没有编程基础时，也从同一章先理解 Agent 与 Harness，再读章内的文件、程序、命令和配置桥梁。

先建立三个概念

Agent 是围绕目标观察、决策、行动并接收反馈的系统。 Code Agent 把这个过程用于理解仓库、修改代码、检查结果和交付。模型负责提出下一步；Agent Harness 是组织输入、调用模型与工具、保存工作状态并控制执行的运行软件。项目里的文件、测试和服务则是它工作的环境。

课程先用六组职责建立关系：输入组织（Input Composition）、模型与工具循环（Model / Tool Loop）、状态与恢复（State / Recovery）、权限与隔离（Permissions / Isolation）、任务推进与协作（Task Progress / Collaboration）、观察与评价（Observation / Evaluation）。第01章通过一个完整的 README 修复例子解释它们，后面的源码章节再逐一展开。图表中的中文解释帮助理解，英文关键词便于与源码和英文资料对应。

第一次读到哪里可以停

本课程以 LLM / Code Agent 与 Agent Harness 为主，分层帮助读者建立概念、理解案例、分析设计与取舍。零编程读者可以从第01章的文件与命令说明、第02章的 Python 阅读卡开始；独立编程、生产安全与工程交付还需要实践经验和单独的能力验证，不能由读完课程自动保证。

以下三站依次衔接，可以在任一站停下。进入新章时先读概览及紧随其后的案例条件；“读到问答”包含问题后的参考答案。停点之后的源码细节可以稍后回查，但不能提前使用尚未展开的保证。

  1. 看懂 Agent 怎样行动。 无需 Agent 先修：从第01章“Agent、模型与运行支撑”读到“意图、执行与接口问答”。零编程读者保留中间的文件、命令和配置读法。此时应能区分 Model、Harness 与 Environment；不能跳过“模型提出请求、程序执行、结果另需验收”的关系。此站建立角色与闭环概念，尚不足以判断具体循环如何保存或恢复。

  2. 读懂一次循环与修复的证据。 先完成上一站，再按顺序读第02章“DefaultAgent 的执行循环”至“消息与执行顺序问答”，第03章“请求、执行与回执”至“测试命令的结果解析”，最后从第04章“从失败输出定位两处问题”读完“失败与修复结果问答”。保留 Python 阅读卡，以及 README-only 假设与真实四文件缺陷的区别；预写模型响应、真实命令、教学推导和测试覆盖各有范围，停止也不等于成功。此站支持解读现有修复过程，尚不代表能独立编程或处理全部异常。

  3. 理解为什么还需要运行保障。 先完成前两站，再读第05章“交互、退出与轨迹”至“退出条件与记录缺口问答”，从第06章场景读完“问题解析”，从第07章正常顺序读完“授权与输入选择问答”，最后从第08章职责地图读完“具体执行路径的比较”。确认（Confirmation）、工具可见性和隔离（Isolation）分别起作用；缺少结果不能证明效果没发生，不能据此盲目重试。此站解释保障需求，尚未给出可直接部署的沙箱或通用恢复实现。

继续理解具体保障时，先沿第09–16章补齐项目环境、语言、身份与工具基础，再读第17章核心阅读和第18章核心阅读。上下文、记忆与评价可沿下方14模块地图的第7、9、14项进入，先读每项列出的前置；第49、58章设计专题也保留各自章首前置，不作为跳过机制解释的捷径。

对完全新手，第01章的文件与命令读法先把项目工具接起来；第02章解释循环代码、shell 与 Bash，第04章在计算前解释取整和取余。案例已经给出处理过程与参考结果，不需要先安装软件或运行命令；阅读源码时，先把名字对应到输入、处理与输出，再看具体写法。

第12–20、23–26章设有“核心路线/核心阅读”和“实现深化”等层次：前半部先说明问题、责任与案例，后半部再追源码接线和更多条件。它们是阅读定位，不表示深化段都能无损跳过；后文用到的案例条件、权限与失败边界仍需一并理解。需要回查具体实现时，可从目录直达对应机制。

已熟悉 TypeScript 类型与异步控制流的读者可略过第10章语言对照；不熟悉时，本章提供后续源码所需的读法。第46章算法桥是选读。第47章呈现跨模块综合设计，第48–62章以问题和完整参考方案串联各项机制。
