第 07 章｜概率（Probability）与张量（Tensor）怎样描述一次预测

本章概览

核心问题：模型（Model）的分数怎样成为概率（Probability），又怎样进入训练（Training）目标？

关键概念：交叉熵（Cross-Entropy，CE）衡量指定目标的负对数值；张量（Tensor）按多个维度组织数；损失掩码（Loss Mask）指定参与位置。

关系主线：从同一输入逐项计算，再比较两份分布与不同平均单位，连接到下一章的参数更新（Parameter Update）。

前情回顾：保存了经验（Experience），谁会用它改变预测

第01章把“改变留在哪里”和“后续谁实际使用”分开。把一句诊断写进外部记忆（Memory），还要由输入组织（Input Composition）程序读回；改变模型参数（Model Parameters），则要由推理程序装载这些数值并计算。两者都可能影响下一次选择，但发生变化的位置不同。

例如，智能代理（Agent）已经修改文件，接下来应当执行规定的测试。运行支撑（Agent Harness）把当前情况组织成输入，模型（Model）据此给不同后续输出打分；分数不会因为人类已经知道正确下一步，就自动偏向它。这些数值究竟怎样连接当前输入与下一次选择？ 本章把这条关系缩小到能逐项算清，再为下一章的参数更新（Parameter Update）准备同一个例子。

本章可以从第01章直接进入。基础第46章已经解释过概率（Probability）、对数概率（Log Probability）和局部学习信号；本章会重新给出马上需要的定义，随后增加具体矩阵（Matrix）、位置和分组的计算，不要求先读完那一章的选读推导。

一个输入，怎样得到三个分数

先固定这一例的条件：目标文件已经读取并修改，规定的测试还没有执行；当前允许执行测试，教学监督（Supervision）把下一步的学习目标规定为“测试”。这是一份新构造的教学情境，不是第01章空格路径项目的真实续跑。我们没有启动真实智能代理（Agent）或工具调用（Tool Call），只用公开全部数值的小模型（Model）观察“指定目标”与“当前选择”之间的差距。

把输出词表（Vocabulary）人为缩成三个符号：<READ>、<TEST>、<DONE>，编号依次为0、1、2，分别用来标记读取、测试和结束。词元（Token）是模型（Model）处理的序列单位，不必等于一个汉字或英文单词。只在本例中，每个构造符号恰好算一个词元（Token）；它们不是从真实工具协议或分词器（Tokenizer）中读取的词元（Token），真实工具名和结构化调用通常不能照这三个符号直接计算。

先看输入怎样表示，再看模型参数（Model Parameters）怎样参与

固定编码器（Encoder）是本例把输入变成数值的程序：它输出特征向量（Feature Vector）h=[1,1]Th=[1,1]^Th=[1,1]T。第一维是固定常数1，第二维表示当前所需材料已经可见。上标 TTT 表示转置（Transpose），这里把横写的两个数竖着排列。这个简化表示没有编码所有任务条件；我们暂时只计算这一个已给定输入，下一章还会讨论不同输入被表示成相同数值时的失败。

编码器（Encoder）在本例中固定不变。参与后续预测的模型参数（Model Parameters）只有矩阵（Matrix）W0W_0W0​ 中的六个数；下标0表示更新前的初值。矩阵（Matrix）是按行、列排列的数，W0W_0W0​ 的每行对应一个候选，每列对应一个输入特征。

令 D=2D=2D=2 为特征维数，V=3V=3V=3 为词表（Vocabulary）大小，则：

分数怎样成为概率（Probability）

现在让三个候选共享一个总量为1的分布。归一化指数函数（Softmax）先对每个分数取指数，再除以所有候选的指数和：

pv=exp⁡(z0,v)∑j=0V−1exp⁡(z0,j),v∈{0,1,2}.p_v=\frac{\exp(z_{0,v})}{\displaystyle\sum_{j=0}^{V-1}\exp(z_{0,j})}, \qquad v\in\{0,1,2\}.pv​=j=0∑V−1​exp(z0,j​)exp(z0,v​)​,v∈{0,1,2}.

exp⁡(x)=ex\exp(x)=e^xexp(x)=ex 是指数函数（Exponential Function）；e≈2.71828e\approx2.71828e≈2.71828。vvv 标记当前候选，jjj 在分母遍历同一位置的全部候选。先算分母：

这个分布依赖的是哪次输入

把条件写全，一项预测可记为：

pW0(xi∣ci).p_{W_0}(x_i\mid c_i).pW0​​(xi​∣ci​).

这是条件概率（Conditional Probability）：在实际条件 cic_ici​ 已给定时，初始参数 W0W_0W0​ 对输出词元（Token）xix_ixi​ 分配多少可能性。iii 是输出位置编号，既不是模型调用（Model Query）次数，也不是执行环境（Environment）的动作（Action）次数。cic_ici​ 可以包括用户目标、可见工具结果，以及当前输出中已经生成的前缀（Prefix），也就是当前位置之前实际出现的部分。

例如，生成测试请求时尚未取得测试结果，就不能把“测试已经通过”放进 cic_ici​。工具调用（Tool Call）执行后返回的信息，要经运行支撑（Agent Harness）组织，才可能成为后续模型调用（Model Query）的输入。换了条件，预测也可能改变；不能将首张表沿整个任务重复使用。

这里的 ppp 是直接由本例归一化指数函数（Softmax）得到的分布。如果真实系统又用采样温度（Sampling Temperature）调整候选的相对比重，或删去低概率（Probability）候选，实际抽样使用的采样分布（Sampling Distribution）也会改变。后续算法需要哪一种概率（Probability），就必须记录并消费那一种，不能仅凭模型参数（Model Parameters）相同便认为相同。

为什么还要计算对数概率（Log Probability）

自然对数（Natural Logarithm）ln⁡\lnln 是以 eee 为底的对数函数；ln⁡(ea)=a\ln(e^a)=aln(ea)=a。本例使用它时，负对数信息量的单位称为奈特（Nat，记作 nat）。对数概率（Log Probability）的取值范围也不同：当 0<p≤10<p\le10<p≤1 时，ln⁡p≤0\ln p\le0lnp≤0，而概率（Probability）越小，−ln⁡p-\ln p−lnp 越大。

由 pv=ez0,v/Sp_v=e^{z_{0,v}}/Spv​=ez0,v​/S 可逐项得到：

ln⁡pv=z0,v−ln⁡S,ln⁡S≈1.407605964.\ln p_v=z_{0,v}-\ln S, \qquad \ln S\approx1.407605964.lnpv​=z0,v​−lnS,lnS≈1.407605964.

指定目标 <TEST> 的负对数值为1.407605964 奈特（Nat）。它稍后成为损失（Loss）——按目标计算、供优化程序使用的数值；目前并没有加入任务奖励（Task Reward），即对完成情况的反馈分数，也没有经过任务判定器（Grader）的成功评价。判定器（Grader）是按任务规则检查结果的程序，与这里的概率（Probability）计算职责不同。

对数概率（Log Probability）还把一串相乘改成相加。对于同一段自回归输出（Autoregressive Output），即每个位置依据已生成部分继续预测的输出，令 x1,…,xnx_1,\ldots,x_nx1​,…,xn​ 为这段的 nnn 个词元（Token），ccc 为段开始时固定的输入，x<ix_{<i}x<i​ 为第 iii 个位置之前的内容，则：

pW0(x1,…,xn∣c)=∏i=1npW0(xi∣c,x<i),ln⁡pW0(x1,…,xn∣c)=∑i=1nln⁡pW0(xi∣c,x<i).\begin{aligned} p_{W_0}(x_1,\ldots,x_n\mid c) &=\prod_{i=1}^{n}p_{W_0}(x_i\mid c,x_{<i}),\\ \ln p_{W_0}(x_1,\ldots,x_n\mid c) &=\sum_{i=1}^{n}\ln p_{W_0}(x_i\mid c,x_{<i}). \end{aligned}pW0​​(x1​,…,xn​∣c)lnpW0​​(x1​,…,xn​∣c)​=i=1∏n​pW0​​(xi​∣c,x<i​),=i=1∑n​lnpW0​​(xi​∣c,x<i​).​

第一行使用条件链式法则（Chain Rule of Probability），不要求各位置独立；后面每一项已经以此前内容为条件。第二行使用“乘积的对数等于对数之和”。跨模型调用（Model Query）发生摘要或重新检索时，需要采用那次实际输入（Actual Input），不能把这条同段公式解释成所有历史永远完整拼接。

为看清中间数字，另给长度为2的构造符号序列：首项 <TEST> 的概率（Probability）沿用0.244728471；在包含首项的新前缀（Prefix）下，第二项 <DONE> 的条件概率（Conditional Probability）另行给定为0.8。这不是原矩阵（Matrix） W0W_0W0​ 算出的第二项，也不把两个标签解释成实际工具已经执行。

相同的数学结果，也需要稳定的数值计算

给所有未归一化分数（Logits）共同加1000，数学上的概率（Probability）不变：每项指数都多乘 e1000e^{1000}e1000，分子与分母会约去这个共同因子。但程序直接计算 e1001e^{1001}e1001 可能发生上溢（Overflow），超过数值类型能表示的范围。

稳定做法是先减去最大分数 m=max⁡jz0,jm=\max_j z_{0,j}m=maxj​z0,j​，再计算对数归一化指数函数（Log-Softmax）：

pv=ez0,v−m∑jez0,j−m,ln⁡pv=(z0,v−m)−ln⁡ ⁣(∑jez0,j−m).\begin{aligned} p_v &=\frac{e^{z_{0,v}-m}}{\sum_j e^{z_{0,j}-m}},\\ \ln p_v &=(z_{0,v}-m)-\ln\!\left(\sum_j e^{z_{0,j}-m}\right). \end{aligned}pv​lnpv​​=∑j​ez0,j​−mez0,v​−m​,=(z0,v​−m)−ln(j∑​ez0,j​−m).​

本例 m=1m=1m=1，平移后分数为 [0,−1,−2][0,-1,-2][0,−1,−2]，指数和为 1+e−1+e−2≈1.5032147241+e^{-1}+e^{-2}\approx1.5032147241+e−1+e−2≈1.503214724，其自然对数（Natural Logarithm）为0.407605964。以测试为例，−1−0.407605964=−1.407605964-1-0.407605964=-1.407605964−1−0.407605964=−1.407605964，与刚才一致。共同加1000再减最大值，仍得到同一组 [0,−1,−2][0,-1,-2][0,−1,−2]。

下面第二段代码承接 z0。函数输入是本例有限、非空的分数列表，输出是各候选的对数概率（Log Probability）；先算 shifted，再算共同归一化常数，最后逐项相减。需要普通概率（Probability）时才取指数。

def log_softmax(scores):
    top = max(scores)
    shifted = [value - top for value in scores]
    log_sum = math.log(sum(math.exp(value) for value in shifted))
    return [value - log_sum for value in shifted]

log_p = log_softmax(z0)
p = [math.exp(value) for value in log_p]
shifted_log_p = log_softmax([value + 1000 for value in z0])
assert max(abs(a - b) for a, b in zip(log_p, shifted_log_p)) < 1e-12
assert math.isclose(sum(p), 1.0)
print([round(value, 6) for value in p])
print([round(value, 6) for value in log_p])

实际输出为 [0.665241, 0.244728, 0.090031] 与 [-0.407606, -1.407606, -2.407606]，共同平移的断言也通过。这种顺序还避免先把极小概率（Probability）算成0再求对数；后者会把原本有限的结果误变为无穷。它是数值实现问题，不能解释成模型（Model）忽然更不确定。稳定求值的依据可见 Deep Learning 第4章的相应讨论。

一个指定目标，怎样成为损失（Loss）

回到原来的单次预测。监督（Supervision）是为学习指定目标的信号，本例由教学条件规定“下一步应测试”。把它写成独热目标（One-Hot Target）q=[0,1,0]Tq=[0,1,0]^Tq=[0,1,0]T：只有目标编号1的权重（Weight）为1，另外两项为0。这里的权重（Weight）是每项在求和中所乘的系数。

交叉熵（CE）按照这份目标分布，对预测的对数概率（Log Probability）取负后加权求和：

ℓ=H(q,p)=−∑v=0V−1qvln⁡pv.\ell=H(q,p)=-\sum_{v=0}^{V-1}q_v\ln p_v.ℓ=H(q,p)=−v=0∑V−1​qv​lnpv​.

H(q,p)H(q,p)H(q,p) 是交叉熵（CE）的记法；ℓ\ellℓ 表示将这个数用作当前单位置损失（Loss）。qvq_vqv​ 与 pvp_vpv​ 对应同一词表（Vocabulary）中同一候选，均为无量纲概率（Probability），损失（Loss）的信息量单位为奈特（Nat）。本例直接代入：

ℓ≈−[0×(−0.407605964)+1×(−1.407605964)+0×(−2.407605964)]≈1.407605964 nat.\begin{aligned} \ell &\approx-[0\times(-0.407605964) +1\times(-1.407605964) +0\times(-2.407605964)]\\ &\approx1.407605964\ \text{nat}. \end{aligned}ℓ​≈−[0×(−0.407605964)+1×(−1.407605964)+0×(−2.407605964)]≈1.407605964 nat.​

因此它回答“预测给指定目标分配了多少概率（Probability）”。它不会检查指定目标本身是否正确；如果把尚未测试就结束标成正确答案，也能算出合法的交叉熵（CE）。监督（Supervision）是否合适仍是另一份责任。

第三段参考代码把目标与预测接起来。q 是明示输入；核心运算就是逐项乘以 log_p、求和、取负号，没有隐藏的训练（Training）过程。

q = [0.0, 1.0, 0.0]
loss = -sum(target * lp for target, lp in zip(q, log_p))

深化：目标也有不确定性时，比较什么

现在明确改变监督（Supervision）条件，预测 ppp 仍保持原值。另一份教学监督（Supervision）给出软目标（Soft Target）q=[0.2,0.7,0.1]Tq=[0.2,0.7,0.1]^Tq=[0.2,0.7,0.1]T：它对三个候选都分配了概率（Probability），最大比重仍给测试。这三个数是完整给定的分布，不是从一次抽样动作猜出来的。

交叉熵（CE）仍按相同公式计算，只是三项都会参与：

把比值的对数拆成相减，可以看出三个量怎样相连：

深化到张量（Tensor）：哪条轴在数候选

刚才只有一个输入、一个预测位置。训练（Training）程序通常会把多个条件样本（Conditional Sample）和多个位置放在同一批次（Batch）中一起处理；这里每份条件样本（Conditional Sample）包含一次调用的输入与目标。张量（Tensor）是按若干维度排列的数；每个维度对应一条轴（Axis），必须说明它数的是谁。

本节先定义一种存储约定，不把它当作所有训练（Training）库的接口。BBB 是批次（Batch）中的模型调用（Model Query）数，LLL 是对齐后补齐到共同长度的目标位置数，VVV 是每个位置的词表（Vocabulary）大小。于是：

Z∈RB×L×V,Y∈{0,…,V−1}B×L,M∈{0,1}B×L.Z\in\mathbb R^{B\times L\times V}, \qquad Y\in\{0,\ldots,V-1\}^{B\times L}, \qquad M\in\{0,1\}^{B\times L}.Z∈RB×L×V,Y∈{0,…,V−1}B×L,M∈{0,1}B×L.

ZZZ 保存未归一化分数（Logits）；YYY 保存目标的整数编号；MMM 是损失掩码（Loss Mask），用0或1指定哪个目标位置直接参与当前损失（Loss）。Z[b,l,v]Z[b,l,v]Z[b,l,v] 指第 bbb 次调用、第 lll 个目标位置、第 vvv 个候选，其中下标均从0开始。

图中箭头表示先选调用、再选位置，最后才对候选归一化（Normalization），也就是把同一位置的候选数值变成总量为1的分布。它不是把整个三维数组共同除以一个总和。

这里沿 VVV 求和，得到每个位置自己的概率（Probability）分布；沿 BBB 或 LLL 混合候选，会让别的输入参与当前选择的归一化（Normalization），改变模型（Model）要计算的问题。下一节再给具体的 B=2,L=3,V=3B=2,L=3,V=3B=2,L=3,V=3 数字，先单独解决位置究竟怎样对齐。

另用五个位置标签表示一段参考序列：[P0, P1, A0, A1, EOS]。P 标记给定前缀（Prefix），A 标记参考回答，EOS 表示序列结束标记（End-of-Sequence，EOS）。这些是示意标签，不是前面三候选词表（Vocabulary）的新成员。

这里原始长度 T=5T=5T=5。按“输入前 T−1T-1T−1 项，预测后 T−1T-1T−1 项”的约定，得到 L=T−1=4L=T-1=4L=T−1=4 个对齐位置。下面每一行就是一对“已经看到什么→随后预测什么”，与稍后的三槽批次（Batch）是两个独立示例。

读到 P1 时预测 A0；读到参考 A0 后再预测 A1。训练（Training）时用已有参考内容作为后续输入，叫教师强制（Teacher Forcing）。它仍要求为每个目标采用相应的前缀（Prefix）：如果使用已经读到 A0 的分数来评价 A0 本身，就把要预测的答案提前放进条件了。

若训练（Training）接口已经在内部完成移位（Shifting），调用方再手动移一次，也会把目标错开；必须以所用模型（Model）的具体接口为准。表格展示的是完整的对应关系，不宣称所有接口都由调用方执行同一操作。

损失掩码（Loss Mask）控制哪一项参与，不控制全部可见性

上表第一项的 M0=0M_0=0M0​=0，因为此设计不优化给定前缀（Prefix）的预测；参考回答及结束项取1。补齐（Padding）是在较短序列末尾添加占位位置以便组成数组，这些位置通常也不参与这项损失（Loss）。

损失掩码（Loss Mask）与注意力掩码（Attention Mask）职责不同：前者选择直接进入目标的项，后者按具体接口指定输入位置之间的可见关系。因果掩码（Causal Mask）是限制当前位置不能偷看未来的规则。不能因为目标位置被设为0，就认为其输入内容已经从计算中消失。

例如，表中 P0、P1 仍在预测 A0 的条件里。如果编码器（Encoder）也参与训练（Training），后续损失（Loss）的梯度（Gradient）——各参数对这个数值的局部影响，下一章会逐项计算——仍可能通过这些输入的计算路径影响参数。屏蔽一个损失（Loss）位置，不等于冻结参数（Parameter Freezing）；后者是取消某些参数的更新资格。本章的小模型（Model）固定编码器（Encoder），是另行明示的条件。

还有一个更直接的失败：工具实际返回“读取失败”，导出记录时却将前缀（Prefix）改成“读取成功”。即便篡改段的损失掩码（Loss Mask）全为0，后面的输出也已经在另一份输入下计算。正确的位置选择不能修复虚假的执行轨迹（Trajectory）。

交给训练（Training）库前，核对类别轴和目标接口

本章把未归一化分数（Logits）存为 [B,L,V][B,L,V][B,L,V]，不表示库会自动找到最后的词表（Vocabulary）维。例如 PyTorch 的 CrossEntropyLoss 对有批次（Batch）的输入把第1轴当类别轴，可以将本例展平为 [BL,V][B L,V][BL,V]、整数目标展平为 [BL][B L][BL]，或者将分数转为 [B,V,L][B,V,L][B,V,L]、目标仍为 [B,L][B,L][B,L]。两种布局都把相同目标与对应候选向量交到接口规定的位置。

这个接口接收未归一化分数（Logits），并在损失（Loss）内部完成所需变换；调用前再做一次归一化指数函数（Softmax），就会把概率（Probability）当新分数输入，改变计算。

还要区分两种目标入口。整数目标可以指定忽略索引（Ignore Index），用一个专用编号排除位置；本例未使用类别权重（Class Weight），即未额外放大某类目标的损失（Loss），也未使用标签平滑（Label Smoothing），即未把确定目标的一部分比重分给其他类别。因此若采用这个入口计算参与位置均值，分母才是未忽略位置数。有类别权重（Class Weight）时，均值分母按接口中的相应规则确定。软目标（Soft Target）则与分数同形状，ignore_index 不适用于这种入口；调用方还须确保概率（Probability）合法且沿类别归一化（Normalization），不能依赖接口自动验证。由此不能把某个参数名相同当作监督（Supervision）与损失掩码（Loss Mask）语义也相同。

本章实际执行的是七段 Python 标准库参考代码，没有运行 PyTorch 或真实模型（Model）的训练（Training）。接口对照说明数据怎样被消费者（Consumer）理解，并不把查过文档写成已经取得训练（Training）效果。

从计算结果作出参考判断

问题。 所有候选分数共同提高1000，能说模型（Model）对 <TEST> 更有把握了吗？

参考答案。 不能。归一化指数函数（Softmax）使用候选之间的相对分数，共同平移不改变概率（Probability）。本例稳定计算返回相同分布；直接指数计算上溢（Overflow）是数值故障。

问题。 改成软目标（Soft Target）后，交叉熵（CE）从1.407606变成1.307606，说明参数更新（Parameter Update）有效吗？

参考答案。 还没有执行参数更新（Parameter Update）。预测 ppp 不变，改变的是目标 qqq 及其求和权重（Weight）。只有固定了要比较的条件，才能把损失（Loss）变化归到相应干预（Intervention）；下一章会真正计算一次参数更新（Parameter Update）。

问题。 执行轨迹（Trajectory）只保存了已选词元（Token）的概率（Probability），足够计算这里的全词表（Vocabulary）库尔贝克–莱布勒散度（KL）吗？

参考答案。 不足。公式对完整、对齐的两份分布求和，还缺未选候选的数值。采样估计可以是另一个明确算法，但不能将缺失项填0后继续声称得到精确结果。

问题。 两种平均都符合各自公式，为什么仍要预先选择？

参考答案。 它们决定哪些位置更影响损失（Loss）和后续更新。词元（Token）等权使长调用占更多总权重（Weight）；模型调用（Model Query）等权先在各次内部平均；完整采样尝试（Rollout）等权还要恢复尝试分组。计算正确不能替代目标选择，也不能替代未来任务评价。
