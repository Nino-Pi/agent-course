Agent 前沿进阶能力增长、自主研究与自我改进

第 06 章｜下一次读取怎样改变判断

本章概览

核心问题：资料互相矛盾、读取也有成本时，Agent应该先查什么，怎样知道已经足以回答？

关键概念：主动取证：根据当前缺口选择下一观察；信息价值：新观察对决策的预期帮助；证据状态：区分已支持、已否定和仍未知；新鲜度：材料是否适用于当前时点；停止规则：根据证据、权限和预算结束查询。

关系主线：以同一资料研究任务比较顺着排名读与按缺口取证，追踪查询、回读、上下文和最终回答；再用缓存失效与服务故障说明，读得更多不保证证据更完整。

先把“还不知道什么”写成能改变行动的问题

本章硬前置是第05章的共同核心。沿用其中“材料必须被实际消费者读取”的定义，本章只改变单次任务中的查询与输入组织，模型参数和跨任务记忆保持不变。这里的资料研究指查找、核对和综合已有资料；找到了可靠答案，不因此成为原创科研。

另设K-C的一项独立任务。青岚是虚构的笔记服务，本次查询时点改为2026年7月2日12:00，资料与站点副本按下表重新给定；第04章6月15日的当前状态不延用。用户问：“青岚现在给新工作区设置多少天的默认留存？既有工作区会被统一改成这个数吗？我们的河岸工作区目前是多少天？”河岸在5月建立，用户没有提供管理员配置。

本次授权只允许读公共资料并生成答复草稿，不允许登录管理员页、修改留存或发送公告。两种策略从同一冻结站点副本、同一初始缓存和空的任务工作记录开始；固定同一模型M0、工具接口、输入格式和输出规则。差别只有下一次查询选择，不给主动取证方额外资料。

每个试次最多6次模型决策、5次工具调用、120秒行动时间。最终报告也算一次模型决策；独立评分最多再用20秒。总费用上限为20个教学费用点，含评分的2点。失败读取和重试照常计数。以下模型决策与网页行为是完整给定的教学过程；本章后面的普通Python程序只运行策略与账本模拟，没有运行模型或访问真实青岚服务。

判定合同提前固定：答案应给出有当前公共依据的新工作区默认值、既有工作区是否自动改变，并明确河岸当前值的证据缺口。前两项未回答，或把河岸当前值猜成默认值，均为有效F；三项满足则为S。外层评分器持有冻结资料的真值，若它自己无法工作才是评分U。准确报告查询失败仍有价值，但不自动满足完整交付要求。

资料都在站点里，不等于都已进入输入

下面给读者列出这个微型环境的全部相关原文。模型初始知道任务、公共读取范围，以及搜索、缓存读取和公共页面刷新的工具合同；原文在被调用返回之前不会出现在它的输入中。

资料身份与来源 本例原始正文或返回内容 时间与适用范围
B：一篇转述博客 “青岚进入30天留存时代。切换即将开始，团队可以据此安排资料整理。” 6月18日发布；没有交代既有工作区规则，不是当前策略页
N：官方调整公告 /notice “计划自7月1日启动新工作区默认30天的调整。实际生效情况以当前策略页 /defaults 为准；既有工作区规则见 /faq。” 6月1日发布；宣布计划，不单独确认7月2日已经生效
P旧：/defaults 的缓存副本 “当前新工作区默认留存90天。” 最后核验于5月15日；正文版本为5月1日版，没有7月2日的重新核验结果
P新：官方当前策略页 /defaults “7月1日调整已生效；当前创建的新工作区默认留存30天。” 本例站点副本核验时点为7月2日12:00；这是刷新后才返回的版本
FAQ：官方常见问题 /faq “既有工作区不会随本次调整自动改成30天，继续采用各自当前配置。管理员可以另行调整；某个工作区当前值须查其管理设置。” 当前站点副本中的有效说明
初次搜索回执 按B、N、P旧给出三个候选及上述标题、日期、路径；明确truncated=true 只返回排名前3项，不承诺站点只有3篇材料

搜索返回的P旧是缓存候选。普通缓存读取只取得P旧；显式刷新/defaults才向本例的当前站点副本核验，并返回P新。公告中的/faq路径是新发现的读取入口，不能因为初始搜索没返回FAQ就说它不存在。

读完搜索回执后，当前问题可以分成三格：G1：新工作区现在的默认值；G2：既有工作区是否自动变化；G3：河岸的实际配置。 G1需要当前政策，G2需要适用范围，G3需要该工作区的配置观察。这种分解的用处是让每次读取有明确消费者：准备回答哪一格，哪种返回会改变下一动作。

G3已暴露权限限制：任务没有提供管理员配置，也没有管理员读取权限。此时尚未取得河岸当前值；策略不能搜索十次“河岸30天”就把公共默认值当作私人配置。后续回读还要确认公共政策是否允许对这个既有工作区作进一步判断。

先跟着排名读，会在哪里耗尽机会

设策略R为“搜索，依排名读取前三个候选，再用同一关键词搜索一次”；遇到时间冲突仍不刷新，最后按实际取得的证据回答。它不是所有排序检索器的代表，只是本题固定的比较策略。

工具次序 R实际取得什么 当时仍缺什么
1：搜索“青岚 留存” B、N、P旧三个候选 G1–G3均未闭合
2：读B 看到了30天的转述 不能确认实际生效与既有范围
3：读N 看到了计划日期及/defaults、/faq入口 仍需当前政策和既有规则
4：读P旧 取得5月核验的90天正文 旧观察与新计划并置，不足以确认当前值
5：重复原搜索 仍是相同前三项，仍被截断 没有新增证据；工具预算耗尽

R的诚实答复是：“公告计划改为30天，但当前缓存仍写90天，尚未确认现在的默认值；既有工作区规则和河岸实际配置也未核对。”它正确保留了未知，却没有完成前两项要求，外层给F。若改为按两篇含30天的文字对一篇90天的文字投票，也不能补上生效与适用范围；重复转述不是独立政策证据。

这个失败没有发生在“资料总量不足”。FAQ由已经读到的N直接指向，P新也有明确刷新入口；真正浪费的是冲突出现以后没有改变读取动作。

按缺口取证，观察会怎样推动下一步

策略Q同样先搜索，但优先回读官方公告，再根据公告指出的缺口行动。以下每行的依据只来自该行之前已经取得的观察。

工具次序 下一动作及其依据 新观察怎样改变状态
1：搜索 用任务关键词发现候选 N具有原始公告身份，P旧核验时间较早；决定先读N
2：读N 需要区分“计划”与“当前” N明确把实际生效交给/defaults，并提供/faq；形成两个具体回读入口
3：刷新/defaults P旧不足以回答7月2日的G1 P新写明已生效、当前30天；G1从未知变成有来源的30天
4：读/faq 还缺G2的既有范围 明确“不会自动改”；G2变成有来源的否定，G3仍无配置观察
最终报告 G1/G2已有所需证据，G3超出本次可取得的信息范围 停止查询，给结论、来源和未核项

Q最终草稿为：“截至7月2日12:00，新工作区默认留存30天，当前策略页已确认生效。既有工作区不会因这次调整自动变成30天，仍按各自当前配置。河岸在5月建立，属于既有工作区；我们没有读取它的管理设置，不能据公共默认值判定它当前是多少天。”前两句分别引用P新与FAQ，最后一句依据用户给定的建立时间、FAQ的范围和本次未读取配置这一事实。外层给S。

本例的候选答案也能直接比较：答“所有工作区都是30天”与FAQ冲突；答“当前仍是90天”只使用了过期观察；上述Q草稿能让每个确定结论落到适用证据。选择器检查的是主张、时点、对象和出处是否对应，不是哪份答案更肯定或哪一个数字出现更多次。

这种观察与行动交替的做法与ReAct原方法相通：新观察参与后续查询和答案组织，查询不再是开头一次性的材料准备。原方法也分析了无用搜索和重复行动的失败，不能把这种循环形式当作可靠性的保证。这里没有复现其模型或基准成绩。ReAct原论文

一次读取值得付出多少：先算它能改变什么

只取G1做一个独立数值例子。假设当前30天和90天两个可能状态各占0.5，这是教学给定的不确定性，不是模型置信度测量。答错损失10分，暂不确定损失4分，答对损失0分；这里的损失是为决策设定的代价，不等于前面费用账本的货币。

直接答30或90的平均损失都是0.5×0+0.5×10=5，暂不确定的损失是4，所以还没取证时选择暂不确定。再假设读取当前策略页成功时能完全区分这两个状态，成功率为0.8；失败时没有新增信息，仍选择暂不确定。读取后的预期答题损失为0.8×0+0.2×4=0.8。

若时间和费用已按本题预先选择的尺度折成1分，则这次读取的净价值是4−0.8−1=2.2分。再读一份已知只重复旧公告的副本，不改变这两个状态的相对可能性，其净价值为4−4−1=−1。信息价值比较的是观察之后能否选择更好的动作，不是新增加了多少文字。

更一般地，先按当前证据选择预期损失最小的动作；对某个候选查询，把每种可能返回及其概率列出，在每种返回下重新选动作，再求平均，最后加查询成本。不能先假定会得到想要的结果，再决定去查。这个决策顺序对应信息价值的基本推导；概率、损失和观察可靠性必须有适用条件。信息价值的公式与推导

实际网页会有解析错误、含糊措辞和不可用服务。上述0.8、完全区分和损失权重不是通用常数；如果无法估计，先用“能区分哪两个候选解释、成本多少、失败后怎么办”这三个问题排序，也比把读满预算当目标更明确。一个查询可能只有与另一份材料合起来才有价值，逐篇相关性分数不能自动代表整条证据链的价值。

让下一请求看见结论的条件，而非只剩数字

Q在刷新以后可以整理出以下任务内工作记录；它不跨任务存为长期Memory。

任务时点：7月2日12:00；只读公共资料；不得修改或发布。
G1：当前新工作区30天；来源P新，当前副本核验，已确认生效。
G2：未核；N指向/faq，下一步读取它。
G3：河岸当前值未知；未授权读取管理员设置，不可用默认值代填。
冲突解释：P旧90天是5月观察；N是计划；两者不覆盖P新的当前声明。
来源仍可回读；已用3次工具；最终报告需保留一次模型决策。

最终组装还要带上原始用户目标、适用权限和必要的原文片段。将这份记录缩成“已确认30天，继续完成”会丢失G2/G3与对象范围，后续模型可能把所有工作区都写成30天。节省了输入字数，任务条件却改变了。

在这个小例子中，相关原文很短，可以直接保留。若材料变长，可把长文留在外部，仅将问题、证据摘录、出处、冲突和未完成项送入下一请求；有争议的结论再按出处回读。旧36章的RLM例也把原文和中间结果留在程序环境里，但本题没有需要子模型解释的大批片段，不必添加递归调用。按需读取本身有调用与延迟成本，预先读入少量稳定公共材料和后续定向查找可以组合。上下文检索与按需读取的工程说明

长轨迹采用摘要时，也应保留这些消费条件。ReSum的原方法会保留问题、生成目标相关摘要，再从压缩状态继续；它仍设置实际工具预算。摘要释放窗口空间不会扩大本次读取权限，也不会把已经花掉的查询次数归零。本章没有运行摘要模型，更不把程序整理的一份记录当成ReSum训练效果。ReSum的方法说明

缓存的新鲜度，不能替代主张的时点核对

P旧的90天未必曾经错误；它是另一个时点的正确观察。问题在于用它回答7月2日的当前值。刷新还可能确认内容没有改变，因此“旧副本”也不能反向等于“内容为假”。

缓存读取至少要保留资源身份、表示范围、原版本与核验信息，并遵守当前读取权限。同一路径的不同语言、不同账户或不同工作区表示不能因路径相同就互用。HTTP缓存把可直接复用的新鲜响应和需要重新验证的响应区分开；重新验证可以复用未改变的内容，也可能返回新正文。这种协议上的可复用性，不替研究者判断正文中的“计划日期”是否等于“已经生效”。HTTP缓存的新鲜度与重新验证

本例冻结了7月2日站点，故一次有效回读后可以在本次任务中复用。如果换成真实会变化的网站，必须另外规定哪些主张需要在答复前重新核验，以及如何保留回答的截至时点。即使刚刷新，也没有锁住随后可能发生的页面变化。

可执行参考：观察进入状态以后才决定下一动作

下面用普通Python模拟两种策略。RESPONSES是上表资料的人工结构化转写，用于检查调度、状态和费用；程序没有从网页自动理解自然语言。字段值是各份资料自己的声明，旧90天与新30天都保留，不能将这套小接口冒充通用网页解析器。

current只有在读取的策略页属于本题当前副本时才被接受。False专门表示FAQ正文明确否定自动改变，None表示尚未得到证据；二者不合并。可选页面由搜索命中或已读公告的链接逐步加入，choose不能从整个资料字典偷看答案。refresh故障可以按固定合同重试一次，并优先完成另一个仍可读取的缺口。

代码把拟选动作与资源核对放在同一次决策里：choose先给候选，支付不起时，本轮直接选择最终报告，已计的1点和8秒就是报告成本；没有先发出工具请求再免费追加一次模型报告。真实实现若需要另外调用模型解释被拒绝的动作，必须为那次调用另留预算。

SNAPSHOT = "2026-07-02T12:00"
RESPONSES = {
    "search": {"hits": ["blog", "notice", "cached"], "truncated": True},
    "blog": {"statement": "30天时代", "source": "repost"},
    "notice": {"planned": 30, "starts": "2026-07-01",
               "links": ["refresh", "faq"]},
    "cached": {"current": 90, "snapshot": "2026-05-15", "source": "defaults"},
    "refresh": {"current": 30, "snapshot": SNAPSHOT, "source": "defaults"},
    "faq": {"existing_auto": False, "source": "faq", "snapshot": SNAPSHOT},
}
# 教学费用点、给定工具秒数；不是测得的网络延迟。
COST = {"search": (2, 8), "blog": (2, 5), "notice": (2, 5),
        "cached": (1, 1), "refresh": (3, 8), "faq": (2, 5)}
RANKED = ["search", "blog", "notice", "cached", "search"]

def choose(state):
    seen = state["seen"]
    available = state["available"]
    if "search" not in seen:
        return "search"
    if "notice" in available and "notice" not in seen:
        return "notice"
    if "refresh" in available and state["current"] is None and state["refreshes"] == 0:
        return "refresh"
    if "faq" in available and "faq" not in seen:
        return "faq"
    if "refresh" in available and state["current"] is None and state["refreshes"] == 1:
        return "refresh"       # 最多一次重试；失败也消耗预算
    return None

def run(active, unavailable=False):
    state = {"seen": set(), "current": None, "existing_auto": None,
             "refreshes": 0, "evidence": {}, "available": {"search"}}
    actions, observations = [], []
    spent = seconds = decisions = 0
    for _ in range(6):
        decisions += 1
        spent += 1             # 本轮模型决策的给定成本
        seconds += 8
        action = choose(state) if active else (
            RANKED[len(actions)] if len(actions) < len(RANKED) else None)
        if action is None:
            break
        fee, delay = COST[action]
        # 为最后一次报告决策预留1点/8秒，另为外层评分预留2点。
        if len(actions) >= 5 or spent + fee + 1 + 2 > 20:
            break              # 本轮改作最终报告，已计本轮费用
        if seconds + delay + 8 > 120:
            break
        actions.append(action)
        spent += fee
        seconds += delay
        if action == "refresh":
            state["refreshes"] += 1
        response = ({"error": "503"} if unavailable and action == "refresh"
                    else dict(RESPONSES[action]))
        observations.append((action, response))
        state["seen"].add(action)
        state["available"].update(response.get("hits", []))
        state["available"].update(response.get("links", []))
        if response.get("source") == "defaults" and response.get("snapshot") == SNAPSHOT:
            state["current"] = response["current"]
            state["evidence"]["current"] = (action, SNAPSHOT)
        if response.get("source") == "faq" and response.get("snapshot") == SNAPSHOT:
            state["existing_auto"] = response["existing_auto"]
            state["evidence"]["existing_auto"] = (action, SNAPSHOT)
    complete = state["current"] is not None and state["existing_auto"] is not None
    return {"actions": actions, "observations": observations, "state": state,
            "stop": "enough" if complete else "unresolved",
            "workspace_value": None, "workspace_reason": "settings_not_observed",
            "decisions": decisions, "cost": spent + 2, "seconds": seconds + 20}

for label, active, unavailable in [("R", False, False), ("Q", True, False),
                                    ("Q_503", True, True)]:
    r = run(active, unavailable)
    s = r["state"]
    print(label, s["current"], s["existing_auto"], r["decisions"],
          len(r["actions"]), r["cost"], r["seconds"], r["stop"])

“证据已足够”与“预算已耗尽”是不同停止原因。前者可以给有范围的结论；后者必须保留尚未解决的缺口。权限不够则限制可行动范围，即使信息价值看起来很高，也不能越界读取。

本例允许Q用4次工具便停止，剩余1次不是必须花掉的额度。完整账本中，R为17点、Q为16点，Q_503为20点，均包括失败、最终报告和外层评分。提前停止节省的一点不能单独证明生产收益：这里仅有一个特意构造的任务，没有任务分布、重复试次或真实模型费用。后续对照还应加入公告本身足够、当前页不可用、FAQ与现行页冲突等任务，防止只挑适合Q的样例。

直接问答：多读、少读与读错怎样分别判断

问题。 搜索结果没有FAQ，而公告给了FAQ链接，直接回读算不算改变实验输入条件？

答案。 两边原本都有同样的链接跟随工具和公共读取权限。Q根据实际取得的N选择了新的动作，这是策略差异；没有凭空给它额外正文。如果只有Q被预先告知FAQ答案或得到额外工具，比较条件才改变了。

问题。 两份资料都写30天，为什么仍需要当前策略页？

答案。 B是转述，N是计划，而且N明确把实际生效交给当前页。两份相同数字没有闭合“现在已经生效”的条件，也没有回答既有工作区范围。资料之间共享同一公告时，数量还会高估独立支持。

问题。 刷新成功之后，为什么不能顺便把河岸改成30天？

答案。 刷新只取得公共政策证据，没有取得河岸当前配置，更没有新增修改授权。知道某个默认值与有权更改用户设置是两件事；本题的合法产物仍是草稿。

问题。 摘要更短、工具调用也更少，就能判定上下文策略更好吗？

答案。 还要检查它是否保留了时点、范围、否定与未知，并让下一请求正确消费。若少一次读取恰好遗漏FAQ，成本下降却留下错误的全体30天结论，整项任务仍失败。应连同证据覆盖、最终结果、未知比例和全部成本一起比较。

本章的硬前置是第05章共同核心，不要求训练深化或梯度知识。相关回读：旧36章的输入选择与外部工作状态、旧37章的查询改写与当前正文回读。后续计划继续比较串行修订、独立候选与树式搜索的选择质量和预算分配；它们会使用这里已经闭合的证据状态。
