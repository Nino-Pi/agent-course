Agent 前沿进阶能力增长、自主研究与自我改进

训练（Training）深化｜一条记录能支持哪一种更新（Update）

本篇概览

核心问题：同一份成功摘要，为什么能成为新示范，却不足以重放原来的生成过程？

关键概念：真实前缀（Actual Prefix）是生成当时实际可见的编码输入；行为分布（Behavior Distribution）是经过实际解码处理的采样概率（Sampling Probability）；消费者合同（Consumer Contract）规定材料被怎样接收和使用。

关系主线：沿用第05章的来源身份，连接第07–08章的概率（Probability）、位置和更新（Update），逐步构造两种消费者（Consumer），算清接收、拒绝与分组权重（Weight）；最终判断记录足够支持什么，不把局部诊断当成完整训练（Training）。

从“存下了什么”走到“目标实际使用什么”

第05章共同核心已经区分原始执行轨迹（Trajectory）与面向用途的投影（Projection）：把测试入口写进记忆（Memory），还需要将它组装到后续实际输入（Actual Input），再由消费者（Consumer）产生动作（Action），即供执行的下一步请求。本篇沿用这个问题，改看训练（Training）材料。

第07章给出的条件概率（Conditional Probability）回答“已经看见这些输入时，下一个词元（Token）有多大概率（Probability）出现”。词元（Token）是编码后的离散编号。损失掩码（Loss Mask）决定哪些位置计入目标；第08章的梯度（Gradient）则说明目标怎样改变参数。于是，错误的输入、目标位置或权重（Weight），会让完全正确的求导作用于错误问题。这里先把材料接收条件闭合，再进入具体训练（Training）方法。

必要前置是第05章共同核心、第07章的概率（Probability）与位置及第08章的损失（Loss）与更新（Update）。本篇不要求先读完整强化学习（Reinforcement Learning，RL）；它指用交互反馈优化决策的学习方式，具体目标仍要分别定义。

同一调用的修改回执，不能换成最终成功摘要

沿用 P-space-01 / trial=1 / attempt=A1 / call=C3。完整键依次标识任务（Task）、预先安排的试次（Trial）、尝试（Attempt）和模型调用（Model Query）。第05章的C3看到了当前合同、修改回执与测试入口，随后请求测试和读取差异；只有取得测试观察（Observation）后，C4才可能报告结果。此时“测试还没执行”和“测试已经通过”会允许不同的下一步。

如果把最终成功摘要补进C3的输入，得到的就是新条件，不能据此声称复原了当初的条件概率（Conditional Probability）。甚至可读文字完全相同，不同分词编码器（Tokenizer）、聊天模板（Chat Template）、工具序列化（Tool Serialization）或截断，也可能产生不同的真实前缀（Actual Prefix）。前者将文本映射成词元（Token），后几项决定角色、工具结构和实际保留的内容。

原条件的记录至少要能查回：实际输入与输出编号、编码和模板版本、哪些位置由模型（Model）生成、原采样参数及其所对应的模型（Model）。工具观察（Observation）可以进入下一次的条件，但它不会因为与生成文本排在同一个文件里，就自动成为本次模型（Model）生成的目标。

另一条路线是明确构造新示范。假设有权策展的教师已经确认：在“修改完成、尚未验证”的新条件下，参考下一步是执行测试。它可以形成监督微调（Supervised Fine-Tuning，SFT）材料：以确认的输入—目标示范对模型（Model）进行训练（Training）。后续监督微调（SFT）的目标将按这个新条件计算概率（Probability）；来源说明“由摘要策展”，不伪造原来没有记录的采样概率（Sampling Probability）。教师确认是案例给定条件，下面的程序不会仅靠一个教师名字检验示范质量。

先规定两个消费者（Consumer），再要求相应字段

消费者（Consumer） 当前接收条件 接收后实际产生什么
策展监督微调（SFT）样本构造器 来源允许用于开发；输入与目标已经确认；编码与位置明确 模型输入（Model Input）、预测目标和损失掩码（Loss Mask）
带终局判定的行为概率诊断器（Behavior Probability Diagnostic） 原条件可核对；终局为成功（Success，S）或有效失败（Valid Failure，F）；历史行为分布（Behavior Distribution）及版本明确 同一位置在两套明确的生成规则下输出概率（Probability）的相对变化

未知评分（Unknown Score，U）表示当前缺少有效终局判定。本篇第二种消费者（Consumer）有意要求已知判定，因此拒收它；这不是所有概率（Probability）计算都必须先有任务评分的普遍规则。有效失败（Valid Failure，F）可以参与诊断，但不等于其中每个动作（Action）都错，也不等于应该把整段输出当作正确示范。

原始概率（Raw Probability）怎样变成行为分布（Behavior Distribution）

为把数字与字段逐一对应，下面另建一个七符号的教学协议 toy-v1。它不是C3/C4的真实编码日志，也不是第07–08章的六参数的模型（Model）。C3同时请求的另一项差异读取及其输出位置未纳入；本篇只对TEST这一动作（Action）作局部投影（Projection），不能把它称为完整执行轨迹（Trajectory）的重放。

编号 教学含义 当前用途
0、1、2 起始、合同材料、编辑回执 前缀（Prefix） [0,1,2] 表示尚未取得测试结果
3、4、5 读取（READ）、测试（TEST）、报告完成（DONE） 本例允许生成的三个动作（Action）符号
6 测试通过观察（Observation） 另一个前缀（Prefix） [0,1,6] 表示结果已经可见

每个编号在这个微型协议中只表示一个符号，不代表真实文本恰好由一个词元（Token）构成。两个查表策略（Policy）toy-W0 与 toy-W1 规定条件到生成分布的映射；它们根据完整前缀（Prefix）返回七维未归一化分数（Logits）：旧策略（Policy）在当前合适的动作（Action）上放入 ln⁡2\ln 2ln2，新策略（Policy）放入 ln⁡3\ln 3ln3，其他候选的分数均为0。编辑之后合适的是TEST；已有通过观察（Observation）时合适的是DONE。它们也与第05章原案例的底模M0不同。

先算完整词表（Vocabulary），再算允许生成的三个候选

词表（Vocabulary）列出本协议全部七个符号。对编辑后的旧策略（Policy），指数变换后的七个候选分数是 [1,1,1,1,2,1,1][1,1,1,1,2,1,1][1,1,1,1,2,1,1]。直接沿七个词表（Vocabulary）候选归一化，TEST的原始概率（Raw Probability）为：

pold(TEST∣c)=eln⁡26e0+eln⁡2=28=0.25.p_{\mathrm{old}}(\mathrm{TEST}\mid c) =\frac{e^{\ln 2}}{6e^0+e^{\ln 2}} =\frac{2}{8}=0.25.pold​(TEST∣c)=6e0+eln2eln2​=82​=0.25.

允许集合中原指数为1、2、1，经温度（Temperature）缩放后变成1、2\sqrt22​、1。因此：

一项局部概率比（Local Probability Ratio），能诊断什么

对同一前缀（Prefix） ccc 和已选输出 xxx，本篇定义局部概率比（Local Probability Ratio）rrr：

它说明在本例相同处理规则下，新策略（Policy）给这个位置的TEST多分了一些概率质量（Probability Mass）。若误用原始概率（Raw Probability）0.25作分母，得到约1.856406，比较对象就变了。更换权重（Weight）后再用新策略（Policy）算一个数并命名为 old_logp，同样不能恢复历史条件。

当解码规则（Decoding Rule）排除了某个符号，其行为概率（Behavior Probability）可以为0；若旧分母为0，这一比值没有定义，不能随意补一个小数来冒称原分布。当前参考程序仅支持上述允许集合和阈值1；其他规则会明确拒收。

近端策略优化（Proximal Policy Optimization，PPO）等方法也使用概率比（Probability Ratio），但要按各自原方法解释其中的策略（Policy）与采样（Sampling）约定。这里选择的是明确解码处理后的行为分布（Behavior Distribution），仅检查记录充足性。尚无优势估计（Advantage Estimation，即相对基线判断动作（Action）的收益）、裁剪约束、完整训练目标（Training Objective）、参数更新（Parameter Update）或后续交互，不能把下面的计算称为一次近端策略优化（PPO）训练（Training）。

让程序逐步消费这些条件

以下六段Python合起来是可执行参考程序。输入都是公开教学夹具（Fixture），即预设的记录与数值；程序没有抽取随机输出，没有调用语言模型（Language Model），也没有执行原项目测试或更新（Update）参数。为便于对照，它同时演示正常接收与有明确原因的拒绝。

第一段：由版本、前缀（Prefix）与解码规则（Decoding Rule）决定概率（Probability）

LOGITS保存两个版本、两个完整前缀（Prefix）的七维分数。behavior只接受已实现的精确配置，然后取允许的三个候选、除以温度（Temperature）并归一化。它不会遇到未知版本时偷偷套用新版本。

import copy
import math
from collections import Counter

CFG = {"do_sample": True, "temperature": 2.0,
       "top_p": 1.0, "allowed": [3, 4, 5]}
LOGITS = {}
for version, boost in [("toy-W0", 2.0), ("toy-W1", 3.0)]:
    edit, tested = [0.0] * 7, [0.0] * 7
    edit[4], tested[5] = math.log(boost), math.log(boost)
    LOGITS[version] = {(0, 1, 2): edit, (0, 1, 6): tested}

def softmax(values):
    peak = max(values)
    terms = [math.exp(value - peak) for value in values]
    return [term / sum(terms) for term in terms]

def behavior(version, prefix, cfg):
    if cfg != CFG:
        raise ValueError("unsupported_sampler")
    if version not in LOGITS or tuple(prefix) not in LOGITS[version]:
        raise ValueError("missing_policy_or_prefix")
    z = LOGITS[version][tuple(prefix)]
    allowed = cfg["allowed"]
    probabilities = softmax([z[i] / cfg["temperature"] for i in allowed])
    return dict(zip(allowed, probabilities))

减去最大值只为数值稳定，不改变归一化结果。do_sample=True是待核对的采样配置（Sampling Configuration）；这个函数只返回其分布，没有真正调用随机采样器。

第二段：保留来源身份，并把目标移到正确位置

example构造一份记录；key保留完整身份。aligned_view先检查开发用途与编码，再把输入和输出连接，按相邻位置构造预测目标。对本篇一符号输出，关系如下：

预测所在位置 本位置及之前可见的符号 下一位置的目标 损失掩码（Loss Mask）
0 [0] 1，合同材料 0
1 [0,1] 2，编辑回执 0
2 [0,1,2] 4，生成TEST 1

目标数组是 [1,2,4]，但前两个目标属于给定条件，因此损失掩码（Loss Mask）为0；将来构造逐词元损失（Token-level Loss）时，只选择生成的TEST。本篇返回位置合同，没有计算训练损失（Training Loss）或更新（Update）参数。这与“把输入编号全部删除”不同：这些位置依然参与条件编码。

def example(trial, attempt, call, prefix, token, verdict):
    return dict(
        task="P-space-01", trial=trial, attempt=attempt, call=call,
        source_group="P-space-template", split="development",
        encoding="toy-v1", origin="exact-fixture",
        input=list(prefix), output=[token], policy="toy-W0",
        sampler=copy.deepcopy(CFG), logp_kind="behavior",
        old_logp=math.log(behavior("toy-W0", prefix, CFG)[token]),
        verdict=verdict, score={"S": 1, "F": 0, "U": None}[verdict])

def key(row):
    return tuple(row[name] for name in ("task", "trial", "attempt", "call"))

def aligned_view(row):
    if row["split"] != "development" or row["encoding"] != "toy-v1":
        raise ValueError("wrong_purpose_or_encoding")
    if not row["input"] or not row["output"]:
        raise ValueError("empty_input_or_target")
    sequence = row["input"] + row["output"]
    if any(type(token) is not int or token not in range(7)
           for token in sequence):
        raise ValueError("invalid_token")
    n = len(row["input"])
    mask = [int(position >= n) for position in range(1, len(sequence))]
    return sequence[:-1], sequence[1:], mask

n是给定输入的长度；拼接序列中索引从 nnn 开始的符号才由模型（Model）生成。列表循环从索引1开始，是因为第一个符号前面没有输入位置用于预测它。score的1、0与空值仅为当前终局判定的编码，尚未决定任何词元（Token）的奖励（Reward）。

第三段：新示范与原条件诊断分别接收

策展监督微调（SFT）只要求新目标按本例教师合同确认，再构造对齐数组。行为概率诊断器（Behavior Probability Diagnostic）额外要求原条件、已知判定和正确概率（Probability）语义；它重算旧策略（Policy）来核对记录值，再算明确的新策略（Policy）。

def curated_sft(row):
    if row.get("curator") != "teacher-v1":
        raise ValueError("target_not_curated")
    return aligned_view(row)

def scored_ratio_diagnostic(row):
    aligned_view(row)
    if row["origin"] != "exact-fixture":
        raise ValueError("no_original_capture")
    if row["verdict"] not in ("S", "F"):
        raise ValueError("unknown_terminal_score")
    if row["score"] != {"S": 1, "F": 0}[row["verdict"]]:
        raise ValueError("inconsistent_terminal_score")
    if row["logp_kind"] != "behavior" or len(row["output"]) != 1:
        raise ValueError("wrong_probability_semantics")
    token = row["output"][0]
    old = behavior(row["policy"], row["input"], row["sampler"])
    recorded = row["old_logp"]
    if (token not in old or type(recorded) not in (int, float)
            or not math.isfinite(recorded)
            or not math.isclose(recorded, math.log(old[token]),
                                rel_tol=0.0, abs_tol=1e-10)):
        raise ValueError("old_logp_mismatch")
    new = behavior("toy-W1", row["input"], row["sampler"])
    return math.exp(math.log(new[token]) - recorded)

最后一行使用对数概率（Log Probability）的差再取指数；不是把两个对数直接相除。这里的旧策略（Policy）与前缀（Prefix）均来自可核对查表，所以能够重算；真实流程若已失去旧版本或原输入，这个程序不能代替缺失证据。

origin与curator是夹具（Fixture）提供的受信元数据，程序演示的是如何消费来源合同。把字符串改成允许值不能令假记录变真。真实数据流仍需查回原请求、编码过程、用途许可及被授权的策展依据；来源字段本身不是真实性证明。

第四段：在同题记录上看见接收与拒绝

现在给出本次实际选取的三个调用。A1的C3投影为TEST，C4在测试观察（Observation）之后投影为DONE，终局成功（Success，S）。第二个试次（Trial）从相同初态重新开始，A2未验证便报告DONE，终局有效失败（Valid Failure，F）。为A2报告新给局部编号C3；它不是A1同名测试阶段，也不表示A2执行过跳过的测试。

另构造一个未知评分（Unknown Score，U）判定以及五种错误字段变体。变体用于说明拒收原因，不增加独立任务（Task）的数量。

good = example(1, "A1", "C3", [0, 1, 2], 4, "S")
finish = example(1, "A1", "C4", [0, 1, 6], 5, "S")
failed = example(2, "A2", "C3", [0, 1, 2], 5, "F")
unknown = example(3, "A3", "C3", [0, 1, 2], 4, "U")
curated = copy.deepcopy(good)
curated.update(origin="curated-from-summary", curator="teacher-v1", old_logp=None)
raw = copy.deepcopy(good)
raw.update(logp_kind="raw-softmax",
           old_logp=math.log(softmax(LOGITS["toy-W0"][(0, 1, 2)])[4]))
missing = copy.deepcopy(good)
missing["policy"] = "M-unknown"
wrong_prefix = copy.deepcopy(good)
wrong_prefix["input"] = [0, 1, 6]
other_sampler = copy.deepcopy(good)
other_sampler["sampler"]["top_p"] = 0.8

print("sft", curated_sft(curated))
for name, row in [("S", good), ("F", failed), ("U", unknown),
                  ("curated", curated), ("raw", raw), ("version", missing),
                  ("prefix", wrong_prefix), ("sampler", other_sampler)]:
    try:
        print(name, "accept", round(scored_ratio_diagnostic(row), 6))
    except ValueError as error:
        print(name, "reject", str(error))

有效失败（Valid Failure，F）行的DONE在旧、新分布下分别约为0.292893与0.267949，局部概率比（Local Probability Ratio）约为0.914836。程序只报告它变小了；没有把失败输出当作正确目标来强化，也没有根据终局0给每个位置统一贴负面标签。未知评分（Unknown Score，U）则保留其缺失原因，不能补成能力奖励（Reward）0后混入。

切成更多调用，不能凭空获得更大的权重（Weight）

来源身份也决定平均单位。当前只选择A1的C3/C4与A2的报告调用，每个输出一个参与词元（Token）；A1的C1/C2及C3另一工具请求都不在本投影（Projection）中。三个调用属于两个完整尝试（Attempt），仍是同一任务（Task）的两个试次（Trial），不是三个任务（Task）或三个独立样本。

我们先平均每次尝试（Attempt）中选定位置的对数概率变化（Log Probability Change），再对两次尝试（Attempt）等权。选择这个诊断量，是为了完整计算分组权重（Weight）；它不是奖励（Reward）或优化目标（Optimization Objective）。

令 kkk 标识所选尝试（Attempt），总数 K=2K=2K=2；NkN_kNk​ 是其中当前选中的参与位置数，分别为 N1=2,N2=1N_1=2,N_2=1N1​=2,N2​=1。令 δkt=ln⁡r(ckt,xkt)\delta_{kt}=\ln r(c_{kt},x_{kt})δkt​=lnr(ckt​,xkt​)，即第 kkk 次尝试（Attempt）中第 ttt 个位置的对数概率变化（Log Probability Change）。则：

δ‾=1K∑k=1K1Nk∑t=1Nkδkt=14δ11+14δ12+12δ21.\overline\delta =\frac1K\sum_{k=1}^{K}\frac1{N_k}\sum_{t=1}^{N_k}\delta_{kt} =\frac14\delta_{11}+\frac14\delta_{12}+\frac12\delta_{21}.δ=K1​k=1∑K​Nk​1​t=1∑Nk​​δkt​=41​δ11​+41​δ12​+21​δ21​.

本例两个A1位置的对数概率变化（Log Probability Change）都为约0.113721834，A2位置为约−0.089010720。按上述权重（Weight）代入：

δ‾≈14(0.113721834)+14(0.113721834)+12(−0.089010720)=0.012355557.\overline\delta \approx\tfrac14(0.113721834)+\tfrac14(0.113721834) +\tfrac12(-0.089010720) =0.012355557.δ≈41​(0.113721834)+41​(0.113721834)+21​(−0.089010720)=0.012355557.

两个A1位置各占 1/(2×2)=1/41/(2\times2)=1/41/(2×2)=1/4，A2位置占 1/(2×1)=1/21/(2\times1)=1/21/(2×1)=1/2。如果改为对三个位置直接平均，每项就都占 1/31/31/3，A1会占总权重（Weight）的 2/32/32/3，这已经换了问题。两种平均都可以明确定义，不能只在实现中悄悄换分母。

第五段：从完整身份计算当前所选位置的权重（Weight）

counts按完整键的前三项累计参与位置，不按调用数重新定义尝试（Attempt）。由于此诊断器明确只接收单符号输出，本批每行正好对应一个参与位置；若要支持多符号输出，应逐位置返回概率（Probability）并分配权重（Weight），不能只复制本例的每行系数。

selected = [good, finish, failed]
assert len({key(row) for row in selected}) == len(selected)
counts = Counter()
ratios = []
for row in selected:
    ratios.append(scored_ratio_diagnostic(row))
    counts[key(row)[:3]] += sum(aligned_view(row)[2])
weights = [1 / (len(counts) * counts[key(row)[:3]]) for row in selected]
assert math.isclose(sum(weights), 1.0)
mean_log_ratio = sum(weight * math.log(ratio)
                     for weight, ratio in zip(weights, ratios))
print("attempt_token_weights", weights)
print("mean_log_ratio", round(mean_log_ratio, 6))

第五段得到：

这只是两次已选尝试（Attempt）的局部诊断汇总。即使它为正，也不能推出任务成功率提高：正负可能来自不同动作（Action），还没有在未来任务（Task）上评价。如果一个调用再切两段，必须保留身份与位置对应，以相同尝试（Attempt）的所选参与位置总数归一化；不能每段都领取一份完整权重（Weight）。数据筛选后也要记录覆盖范围，不能把不完整投影（Projection）称为完整采样尝试（Rollout，即从规定初态到终止的一次完整采样过程）的训练（Training）。

第六段：核对原始概率（Raw Probability）与实际处理的差别

最后回到最初的TEST，分别调用七维原始归一化和三个动作（Action）的行为分布（Behavior Distribution）。这一步让读者能把公式、数组与实际输出闭合。

对记录充足性作出直接判断

问题。 只保留成功摘要，是否完全失去训练（Training）用途？

参考答案。 不必一概丢弃。它可以成为新策展监督微调（SFT）示范的来源，但必须重新确认输入、目标、用途与责任。它仍不足以证明原模型（Model）当时实际看见什么、按哪种行为分布（Behavior Distribution）生成输出。新示范被接收，不能补齐旧条件缺口。

问题。 有效失败（Valid Failure，F）的DONE不合要求，为什么诊断器还接收？

参考答案。 它判断的是“能否在已知终局条件下比较一个已发生输出的概率（Probability）”，不是“能否把这个输出作为正确示范”。终局信息怎样形成学习信号，哪些位置承担责任，必须交给具体目标定义。未知评分（Unknown Score，U）又是另一种情况，不能先假定为失败再代入。

问题。 有旧对数概率（Log Probability），也算出了局部概率比（Local Probability Ratio），可以用于任意强化学习（RL）方法吗？

参考答案。 不能。不同方法还可能要求采样组（Sampling Group，即共同产生并用于相对比较的一组输出）、奖励（Reward）来源、优势估计（Advantage Estimation）、价值估计（Value Estimation，即对未来回报的预测）、参考分布（Reference Distribution）、更新（Update）限制与新的交互。这里既未构造完整目标，也没更新（Update）参数，更没有未来任务（Task）评价。接收合同只针对当前消费者（Consumer）。

问题。 把三次调用逐行导出，是否已经有三个独立训练（Training）样本？

参考答案。 三行是存储形式。当前来源仍是同一题的两个试次（Trial），其中A1的两次调用前后相关。位置能参加计算，不等于来源统计独立。保留来源组（Source Group）有助于按用途划分；组标签本身不能证明真实独立性。
